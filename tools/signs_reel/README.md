# Ролики «Успей узнать знак»

Вертикальные ролики 1080×1920 для Shorts / Reels / TikTok: на карточке
появляется дорожный знак, зритель получает три секунды на ответ, потом
карточка показывает название знака и строку правила.

```bash
./scripts/make_reel.sh                        # категории и остаток знаков
./scripts/make_reel.sh "Запрещающие знаки"    # собрать выпуск
```

Готовый файл — в `assets/videos/signs_reel/`.

## Откуда берётся содержимое

Всё из `assets/countries/ru/questions/signs.json` и `images/signs/` — тех же
файлов, что читает приложение. Знак не рисуется нейросетью и название не
пишется по памяти: выдуманный знак учит несуществующему правилу, а зритель
уносит ошибку на дорогу. Пояснение под ответом — первое предложение
официального описания, и если оно не годится (ссылка на номер другого знака,
хвост про КоАП, слишком длинное), пояснения просто нет.

Знак попадает в выпуск, только если:

- его название уникально по всей базе — иначе два разных знака дают
  одинаковый ответ и вопрос становится нерешаемым (одно «Примыкание
  второстепенной дороги» на шесть номеров);
- его картинка не используется другим знаком (11 файлов переиспользуются);
- название короче 34 символов — длинное мельчает до нечитаемого;
- в выпуске нет второго знака из той же серии (4.1.x, 5.15.x): они
  отличаются только направлением стрелки.

После сборки номера знаков уходят в `state.json`, поэтому следующий выпуск
той же категории берёт другие знаки. Остаток видно по `--list`.

## Как устроен ролик

| Фаза | Длительность | Что на экране |
|---|---|---|
| интро | озвучка + 0,5 с | субтитры по 1–2 слова на синей плашке |
| показ | 0,8 с | знак, полоса полная, «?» |
| отсчёт | 3,0 с | полоса убывает, тикает метроном |
| ответ | озвучка + 0,9 с (не меньше 2,0 с) | номер по ГОСТ, название, пояснение |
| переход | 0,28 с | карточки едут как страницы в приложении |
| финал | озвучка + 0,8 с (не меньше 5,0 с) | сетка всех знаков выпуска и рекламная плашка |

Над карточкой пусто: ни бренда, ни названия категории, ни цифры таймера —
всё это ничего не добавляло к загадке, а категория и так звучит в интро.
Время показывает одна полоса внизу карточки, цветом: зелёная → жёлтая →
красная. Теней нет: карточку от фона отделяет только цвет.
Финал держится дольше озвучки: по сетке знаков зритель сверяет свои ответы.

Текст в интро идёт **субтитрами по 1–2 слова**, ровно по озвучке,
по одному куску за раз. Полотно из трёх строк зритель прочитает за секунду,
а потом сорок секунд будет слушать уже прочитанное. Длинная фраза режется на
равные части, а не «пока влезает»: жадная нарезка оставляет хвост из одного
слова, и это выглядит обрубком. Границы предложений куски не пересекают
(«…за 3 секунды? Сегодня» — это конец одного вопроса и начало другого), а
число не отрывается от своего слова: «за 3» без «секунд» читается обрывком.

**Точки в субтитрах не ставим** — конец фразы виден и так, а точка на плашке
читается мусором. Вопросительный знак остаётся: он меняет интонацию.
Высота плашки считается по метрикам шрифта, а не по чернилам конкретной
строки, иначе «знаки» и «Успеете» дают плашки разной высоты и текст в них
каждый раз стоит на новой высоте.

## Рекламная плашка

Внизу финала — анимированный `banner.webm` (VP9 с альфой, сделан вручную,
лежит рядом с кодом). Он раскодируется в PNG-последовательность один раз в
`.cache/banner/` и потом читается покадрово с диска: финал проходится один
раз и строго по порядку, держать 300 кадров в памяти незачем.

Альфу VP9 отдаёт только явно указанному декодеру `libvpx-vp9`. Без него
ffmpeg вернёт кадр без прозрачности, и плашка приедет с чёрной подложкой.
Заменить плашку — положить новый `banner.webm` и удалить `.cache/banner/`.

## Фон

`backgrounds.py` держит 10 сгенерированных сцен со знаками
(`tools/signs_reel/backgrounds/*.png`); выпуск берёт свою по хэшу, поэтому
лента не выглядит одинаковой, а один и тот же выпуск всегда пересобирается с
тем же фоном. Догенерить недостающие:

```bash
python3 -m tools.signs_reel.backgrounds
```

На сценах — узнаваемые российские знаки, но нарисованные нейросетью, поэтому
фон остаётся только декорацией: мелкие неточности в нём возможны. Знаки,
которые ролик действительно загадывает, берутся исключительно из
`assets/countries/*/images/signs/` и нейросетью не рисуются никогда.

В фазах загадки сцену забивает брендовый синий (`BG_BLUE_ALPHA`) — на пёстрой
картинке белая карточка теряется. В интро и финале карточки нет, сцена видна
почти как есть, и на ней читается синяя плашка субтитров. Ряд номеров внизу
на синем перевёрнут: текущий знак — белая плашка, остальные прозрачно-белые.

Переход — ровно та же анимация, что между вопросами в приложении
(`QuestionSwipeMotion`: 280 мс, `easeOutCubic`). Кадр повторяет экран приложения:
цвета и радиусы в `config.py` — зеркало `AppColors` и `AppDimensions`,
шрифт — Roboto, ряд номеров внизу — по образцу чипов вопросов.

Звук — две дорожки: голос диктора (Gemini TTS) и тиканье. Музыки нет
осознанно: ноль рисков по копирайту и ничего не спорит с диктором.

Пояснение диктор читает, только если ролик после этого остаётся в пределах
58 секунд — иначе читает одно название, а пояснение остаётся на экране.
После минуты Shorts перестают показываться лентой.

## Что проверяется перед выдачей

1. **Все реплики на месте.** Пропущенный клип не «стоит ноль секунд»:
   сборка останавливается. Иначе ролик выглядит собранным, а звук в нём
   разъезжается с картинкой.
2. **Синтез не договорил от себя.** Каждый клип расшифровывается обратно и
   сравнивается с исходным текстом выравниванием — сравнивать начало
   недостаточно, синтез умеет проглотить слово в середине. Отсебятиной
   считается только «лишнее после почти полностью узнанного текста» — иначе
   сборку блокировали бы ослышки расшифровки: короткое «затор» она стабильно
   слышит как «затвор». Отдельно проверяется длительность клипа: он не может
   звучать сильно дольше, чем нужно на этот текст. Если расшифровка недоступна
   (429 от Vertex), сборка не падает, но печатает предупреждение: озвучка
   НЕ проверена.
3. **Картинка и звук совпадают с точностью до кадра.** Таймлайн считается в
   кадрах, а не в секундах, и длины сверяются до склейки. Расхождение — это
   не «на полсекунды длиннее», а накопленный сдвиг: к концу под карточкой
   звучит уже следующая фраза. Флага `-shortest` в пайплайне нет — он бы
   молча обрезал такой ролик и выдал за готовый.

## Ключи

| Ключ | Зачем |
|---|---|
| `--count 5` | другое число знаков в выпуске (по умолчанию 6) |
| `--voice Rasalgethi` | другой голос Gemini TTS (по умолчанию `Algenib`) |
| `--numbers 3.20 3.24` | взять именно эти знаки, реестр не трогать |
| `--no-notes` | диктор читает только названия |
| `--reuse` | разрешить знаки, которые уже выходили |
| `--skip-verify` | не расшифровывать озвучку обратно (быстрее) |
| `--country by` | другая страна (контент должен быть в `assets/countries/`) |

## Окружение

Системный `/usr/bin/python3` (Pillow, numpy, cairosvg, google-genai),
`ffmpeg` с libx264, шрифт `~/Library/Fonts/Roboto.ttf`.

Проект Google Cloud берётся из `quota_project_id` в
`~/.config/gcloud/application_default_credentials.json` или из
`GOOGLE_CLOUD_PROJECT` — не из константы в коде: захардкоженный проект уже
однажды уронил пайплайн с 403, когда учётные данные пересоздали.

`cairosvg` у системного python не находит libcairo (SIP вырезает
`DYLD_FALLBACK_LIBRARY_PATH`), поэтому `raster.py` подменяет
`ctypes.util.find_library` до импорта. Экспорт `DYLD_*` не помогает.
