# Ролики «Выбери знак» — утверждённый формат

Вертикальное видео 1080×1920, 30 fps: вопрос с появлением каждого слова
по озвучке, четыре канонических знака, полные четыре секунды на выбор,
раскрытие ответа и сравнение, короткий финал со скриншотом в телефоне.
Утверждён владельцем 25.10.2026 по пилоту 001.
Стандарт: [docs/video/sign_choice_reels.md](../../docs/video/sign_choice_reels.md).
`reference_001.json` фиксирует одобренный мастер, SHA-256 видео и скриншота,
точные тайминги, слова и независимые проверки. Следующие выпуски начинают
с этого эталона; первый мастер не перезаписывать.

```bash
python3 tools/sign_choice_reel/prepare.py --out output/sign-choice-001
python3 tools/sign_choice_reel/render.py --out output/sign-choice-001 \
  --screenshot /absolute/path/to/screenshot.png --previews-only
python3 tools/sign_choice_reel/render.py --out output/sign-choice-001 \
  --screenshot /absolute/path/to/screenshot.png
```

Результат нового воспроизведения пилота: `output/sign-choice-001/sign_001.mp4`.
Исторический одобренный мастер в этой папке сохраняет имя
`sign_choice_001_test.mp4`; на рабочем столе он переименован в `sign_001.mp4`.
Реплики и порядок знаков заданы в `episode_001.json`.
Команды с `sign-choice-001` описывают воспроизведение пилота: для нового
прогона выбирать новую папку результата и сохранять утверждённый мастер.
Рецепты серийных выпусков — `episodes/002.json` и далее. В них хранятся
разбивка вопроса на строки, группы субтитров, сравниваемые позиции и подписи.
Внешний вид остаётся тем же, что у утверждённого пилота.

```bash
python3 tools/sign_choice_reel/prepare.py --out output/sign-choice-002 \
  --recipe tools/sign_choice_reel/episodes/002.json --reuse-from output/sign-choice-001
python3 tools/sign_choice_reel/render.py --out output/sign-choice-002 \
  --screenshot output/sign-choice-001/source-screen.png
python3 tools/sign_choice_reel/audit.py --out output/sign-choice-002 --mode voice
python3 tools/sign_choice_reel/audit.py --out output/sign-choice-002 --mode video
python3 tools/sign_choice_reel/deliver.py --out output/sign-choice-002
```

Доставка разрешается после обеих независимых проверок, сверки длительности,
контрольной суммы и полного декодирования готового файла. Имя —
`sign_NNN.mp4`; другой существующий файл не перезаписывается.

`prepare.py` использует существующий Gemini TTS из `tools/signs_reel/audio.py`,
сохраняет кэш по тексту/голосу и выравнивает каждую реплику локальным
`whisper-cli` с моделью `scratch/whisper/ggml-large-v3-turbo.bin`.
При отсутствии ADC используется активный аккаунт gcloud. Токены не пишутся
в файлы или вывод. `voice.json` хранит реальную длительность и границы слов;
совпадение распознанного текста проверяется перед рендером. Пропуски и
повторы вызывают перезапись отдельной реплики. Если Whisper только склеил
слова при полном совпадении нормализованных букв («почетным» / «по чётным»),
граница восстанавливается внутри соответствующего сегмента; это отмечается
в `voice.json`. Изменённые, пропущенные или повторённые буквы так не принимаются.
`--reuse-from` берёт только кэш с тем же хэшем текста, модели, голоса и стиля.

`render.py` строит таймлайн после озвучки. Время выбора не пересекается
с репликами. Вопрос выровнен по центру; каждое слово появляется
по распознанному началу, с коротким мягким проявлением. Видимая часть строки
плавно выравнивается по центру даже в начале фразы. Расстановка
карточек остаётся стабильной. На правильной карточке номер заменяется
векторной галочкой `#2BC280` из текущего `AppThemeColors.light.green`.
Шрифт — Onest из приложения. Нижней подсказки выбора и прежней финальной
строки «Продолжи в игре…» нет.

Исходный скриншот вписывается в геометрическую рамку телефона целиком,
с сохранением пропорций. Сам исходник не изменяется и в Git не добавляется.
Мокап плавно появляется в финале под реплику
«Учи ПДД в играх нашего приложения». Запись финала занимает около 2,6 с.

Рендер использует Pillow, numpy, cairosvg и ffmpeg/libx264. Знаки из SVG
растеризуются существующим модулем `raster.py`, оптические поля обрезаются
при вписывании. Проверки: предварительные кадры, компиляция Python,
совпадение озвучки, целое число видеокадров и совпадение длительности
аудио/видео в пределах одного кадра. `verification.json`, `timeline.json`,
`subtitles.json`, аудио и превью сохраняются в папке результата.

Дополнительное независимое прослушивание готовой речевой дорожки:

```bash
python3 tools/game_reels/crossroads_reel/audit_voice.py --out output/sign-choice-001
```

Голос сводится с тихими тиками и коротким сигналом ответа; итог нормализуется
до -16 LUFS, true peak -1,5 dBTP. Музыки в пилоте нет. Реестр старой серии
`tools/signs_reel/state.json` не затрагивается. Публикация не выполняется.

Фактический инвентарь знаков и разметки можно пересчитать командой:

```bash
python3 tools/sign_choice_reel/capacity.py --out output/sign-choice-capacity
```

Оценка числа содержательных выпусков — в
[расчёте потенциала](../../docs/video/sign_choice_capacity_2026-10-25.md).
Утилита считает каталоги и дубли изображений, а не готовые вопросы.
`interesting_candidates.json` хранит отобранные темы с подковыркой:
40 основных и 10 резервных сверх пилота. Утилита дополнительно проверяет
номера и уникальность четырёх изображений и выводит размеры этих списков.
Формулировки и единственность ответов требуют отдельной сценарной проверки.

`series.json` — сохраняемый реестр выпуска и согласованного плана из
40 основных тем. Пилот — `sign_001.mp4`, первые пять новых тем —
`sign_002.mp4`–`sign_006.mp4`. Осталось 35 основных тем; следующий файл —
`sign_007.mp4` по S06. Реестр содержит SHA-256 и фактические длительности;
медиа остаются в папках прогонов и на рабочем столе.
