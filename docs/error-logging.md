# Сообщения о сбоях в Telegram

Сбои отправляются в тот же `CHAT_ID`, что установки, регистрации и покупки,
с отдельным заголовком 🚨. Токен бота остаётся только на сервере.

- Сервер: ошибки выдачи сессии Google/Apple/Яндекс, неудачная проверка
  покупки, ошибки HTTP 5xx и неожиданные исключения воркера, сбои cron,
  подготовки/записи аналитики в KV, проверки СБП и отправки push.
- Новые версии приложения: ошибки SDK входа, загрузки Яндекс-входа,
  магазина, товаров, запуска/восстановления покупки, сетевой проверки
  Premium/СБП, открытия страницы оплаты, Flutter и необработанные Dart-ошибки.
  Отмена входа или покупки, истёкшая подписка и отсутствие покупок при
  восстановлении не считаются сбоем.

Сообщение содержит этап, технический код, HTTP-статус (когда есть), способ
входа/магазин, версию/платформу/устройство (когда приложение передало их),
ID подтверждённого аккаунта или хеш установки, время события. Ошибка входа
на сервере также содержит ID диагностики из `x-auth-diagnostic-id`.
Произвольные тексты исключений и стеки, OAuth-токены, чеки покупки, заголовки,
URL с параметрами и содержимое пользовательских запросов не пересылаются.

`ErrorReporter` хранит до 50 событий не старше 7 дней, отправляет по 10 через
`POST /api/diagnostics`, повторяет при запуске/возврате приложения и новом
событии. ID и время сохраняются при повторе. Без `SHARED_SECRET` доступ закрыт;
до входа можно сообщить об ошибке, но ID аккаунта проверяется по сессии.

`TelegramQueue` сохраняет диагностику в Durable Object вместе с общей
очередью Telegram, без KV-записи на каждую ошибку. Один тип сбоя с одинаковым
этапом/кодом/провайдером/платформой/версией показывается раз в 10 минут;
следующее сообщение включает число подавленных повторов. Общий предел —
20 сообщений о сбоях за 10 минут. Покупки и регистрации этот предел не
затрагивает. Состояние ограничений и повторов переживает перезапуск воркера;
дедуп повторной доставки ограничен последними 2000 событиями за сутки.

Серверная часть работает после деплоя воркера, в том числе для старых
приложений. Клиентские события требуют обновления мобильной/веб-сборки.
При отсутствии сети события остаются на устройстве. При полном отказе
Cloudflare, аварийном завершении процесса или недоступности самого Telegram
мгновенное сообщение не гарантируется; независимый внешний мониторинг
этот механизм не заменяет.
