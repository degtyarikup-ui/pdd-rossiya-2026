# Маскот: прозрачная WebP-анимация

Самостоятельные ресурсы для согласования. В Flutter/Godot не подключены,
в `pubspec.yaml` не зарегистрированы. Исходная модель и движение остаются
в [Blender/GLB](mascot-3d.md); WebP проигрывает заранее отрендеренные кадры.

## Готовые файлы

Каталог `assets/mascot/raster/`. RGB сжат с потерями (`quality=82`),
альфа без потерь (`alpha_quality=100`). Фон не запечён; тень чёрная
полупрозрачная. Весь цикл 7,2 секунды, повтор бесконечный.

| Файл | Размер, байт | Кадры |
| --- | ---: | ---: |
| `cone-juggling-384-30.webp` | 1 241 890 | 216 |
| `cone-juggling-384-24.webp` | 996 334 | 173 |
| `cone-juggling-256-30.webp` | 1 435 470 | 216 |
| `cone-juggling-256-24.webp` | 1 152 310 | 173 |
| `cone-juggling-poster-384.webp` | 23 344 | 1 |
| `cone-juggling-poster-256.webp` | 19 542 | 1 |

Основной вариант — **384 / 30**: лучше передаёт короткий поворот запястий
и продолжение броска. **384 / 24** экономит около 20% размера; в движении
быстрых шаров шаги заметнее. В этом экспорте 256 px занимает больше байт
из-за особенностей сжатия пересчитанных кадров и альфы; преимущество этого
варианта — меньший размер декодируемого кадра, а не меньший файл.

`manifest.json` содержит фактические размеры, SHA-256, длительности,
частоту, число кадров, настройки кодирования и хеш исходного GLB.
24 fps использует 41/42 мс на кадр и последний укороченный кадр, чтобы
сохранить ровно 7200 мс. Конечная поза не дублируется лишним стоп-кадром.

## Предпросмотр

```bash
python3 tools/mascot/serve_model.py
# http://127.0.0.1:8794/webp.html
```

`tools/mascot/webp_viewer.html` показывает настоящий файл через обычный
`<img>`. На странице нет Three.js, WebGL, canvas и своего кадрового цикла.
Есть выбор экспорта, размеров и фонов, включая шахматную подложку.
Пауза, скрытая страница и уменьшение движения переключают изображение на
постер; возобновление начинает анимацию заново. Во время воспроизведения
постер скрыт, поэтому прозрачные участки не накладываются дважды.

## Повторный экспорт

Нужны Chrome, Node с Playwright и Python с Pillow/libwebp. Для Node
Playwright должен находиться в `NODE_PATH` либо обычном `node_modules`.
На этой машине использовались Pillow 12.3.0 и libwebp 1.6.0.

```bash
# Сервер предпросмотра должен уже работать.
node tools/mascot/render_webp_frames.cjs
python3 tools/mascot/encode_webp.py
python3 tools/mascot/check_webp.py assets/mascot/raster/cone-juggling-384-30.webp \
  --source-dir output/mascot/webp-source/384
flutter test tools/mascot/webp_codec_probe_test.dart --reporter expanded
```

Рендер использует ту же сцену, камеру, свет и материалы, что согласованный
3D-предпросмотр. В режиме `?capture=1` WebGL-буфер прозрачный. Небольшой
запас кадрирования удерживает все движущиеся тени внутри изображения;
на границе всех 345 уникальных исходных PNG альфа равна нулю.

Исходные кадры и отчёты лежат только в игнорируемом `output/mascot/`.
При изменении модели или настроек рендера старый `webp-source` нужно
переместить перед новым запуском: защита хеша не даст смешать старые кадры
с новыми. Список кадров и точное время хранятся в `source.json`.

## Проверки и ограничения измерений

`check_webp.py` независимо читает RIFF/ANMF и декодирует композицию кадров:
проверяет длительность, частоту, повтор, совпадение альфы с PNG, отсутствие
обреза и свечения тени, а также переход через шов цикла. RGB имеет потери;
оценка качества по композиции 384 px — примерно 40 дБ PSNR.

`webp_codec_probe_test.dart` проверяет все четыре файла штатным кодеком
установленного Flutter: размеры, все кадры, прозрачность, длительность и
переход на следующий цикл. Отчёт с измеренным временем декодирования —
`output/mascot/flutter-webp-codec-report.json`. Это desktop test engine;
числа не являются замером телефона или release-профилем приложения.

Браузерная проверка покрывает реальные WebP, все фоны, мобильную ширину,
повтор, постер, уменьшение движения и отсутствие запросов к 3D-ресурсам.
Финальный размер файла не равен памяти: один RGBA-кадр 384 px занимает
0,5625 МиБ. При интеграции не нужно заранее распаковывать весь цикл;
нагрузку на слабом Android следует измерить отдельно.
