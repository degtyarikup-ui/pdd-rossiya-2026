# Игра на Godot — план до полной замены старой (WebView) игры

Составлен 2026-10-12, ветка `game-rewrite`. Порядок — по важности для игрока.
Каждый этап заканчивается проверкой на Pixel 9 Pro XL (и iPhone 11, где есть iOS).

## 0. Дрожание на углах перекрёстков и изгибах (блокер)

Три прохода «на глаз» убрали часть наложений, но углы всё ещё дрожат: нужна
диагностика, а не догадки.

1. **Найти виновника.** Отладочный режим `--zfight`: каждой поверхности свой
   цвет (сеть / запечённая сцена / улица / бордюр / разметка), а также кадр
   «сколько слоёв лежит ближе 3 см друг к другу». Снять три угла перекрёстка и
   кольцо на телефоне и на Mac.
2. **Возможные причины, их проверить по очереди:**
   - тротуар сети и запечённые газоны или плитка сцены на дугах: фильтр
     `_without_baked_ground` отсекает только строго плоские треугольники, а дуги
     в экспорте триангулированы с перепадом в доли миллиметра;
   - крышки бордюров (верх стены) в запечённой сцене стоят на высоте тротуара
     сети;
   - короткие сегменты бордюров сети на дуге перекрывают друг друга концами
     (стык под углом даёт две грани в одном месте);
   - разметка (0,04) против асфальта на `near = 2.0` на дальнем плане.
3. **Решение без хрупких фильтров:** из выгрузки сцены брать только объекты
   (здания, деревья, знаки, светофоры), а землю, тротуары, газоны и бордюры
   строить сетью целиком. Для этого `build.py` должен уметь газоны и клумбы
   (слой `lawn` поверх тротуара, без совпадения высот, отступ ≥ 3 см).
4. Тест: скрипт сравнивает высоты всех горизонтальных треугольников сцены и
   сообщает пары ближе 3 см на площади больше 0,05 м². Ноль пар во всех 153 сценах.

## 1. Встраивание в приложение (сделано наполовину)

| Платформа | Сейчас | Что сделать |
|---|---|---|
| Android | новая игра, отдельный экран, процесс `:game` | проверить запуск и возврат; Play Asset Delivery для 85 МБ игры, если AAB превысит лимит |
| iOS | старая игра | собрать Godot из исходников как библиотеку (`library_type=static_library`, без `main`), экран `GodotViewController` в Runner, мост — Swift-плагин `PddHost`; запасной путь — отдельное приложение не годится |
| Веб (pdd-drive.ru/app/) | старая игра | веб-экспорт Godot (`web_nothreads`, без SharedArrayBuffer) в `iframe`, мост через `postMessage`; проверить вес (~30 МБ движок + сцены по требованию) |

После iOS и веба — удалить `assets/game/` из Flutter (≈100 МБ в каждой сборке).

## 2. Что было в старой игре и чего нет в новой

### 2.1 Лобби и гараж (Flutter + рендер машины Godot)
- Стартовый экран: машина на подиуме, вращение пальцем, листание моделей,
  выбор цвета, «Новая», рекорд, заезды, рейтинг, «Продолжить заезд» / «Новый заезд».
- **Как:** лобби оставить на Flutter (`game_lobby.dart`), а подиум рисует Godot:
  экран игры открывается сразу в режиме `--lobby`, Godot показывает гараж,
  Flutter-элементы — поверх через собственный UI Godot (проще) **или** перенести
  лобби целиком в Godot (`lobby.gd`) с данными из приложения (список машин,
  открытые модели и цвета) в аргументах. Рекомендую второе: один экран, нет
  переходов между процессами.
- Модели машин игрока: в Godot сейчас только `hatch` — выгрузить все модели
  `gameVehicleIds` и цвета `gamePaintColors` (`export_models.cjs`).
- Миниатюры для гаража во Flutter больше не нужны.

### 2.2 Открытие машин за правильные ответы
- `GameGarageService.recordCorrect()` → церемония `game_reveal_overlay`.
- **Как:** Godot шлёт `answer` {correct} через `PddHost.send`; плагин копит, при
  выходе Flutter вызывает `recordCorrect` N раз и показывает открытие после
  заезда. Сразу во время заезда — только если перенесём церемонию в Godot.

### 2.3 Итоги заезда и разбор ошибок
- Старый `game_over_dialog`: очки, рекорд с конфетти, «Попробовать снова»,
  «Разобрать ошибки» (вопросы из базы), рейтинг.
- **Как:** Godot уже отдаёт `mistakes` (id сцен). Во Flutter после возврата —
  экран итогов (переиспользовать `game_over_dialog.dart`) + `_reviewMistakes`
  по id. «Попробовать снова» = новый запуск игры.

### 2.4 Экономика заездов
- Сделано: списание заезда, окно «нет заездов».
- Нет: продолжение прерванного заезда (в старой — пауза и возврат в лобби без
  потери). **Как:** сохранять `Run` в `user://run.json` при выходе, передавать
  `--resume` при следующем входе.

### 2.5 Вопросы и подсказки
- Нет: обучение при первом входе (3 подсказки, «жми газ»), картинка билета в
  объяснении (в новой есть по плашке — ок), ИИ-разбор вопроса, переход к
  вопросу в разделе билетов.
- **Как:** подсказки — в Godot (`ui.gd`), флаг «видел» хранить в `user://`.

### 2.6 Содержание
- 112 из 153 перекрёстков в игре; 41 — регулировщик (нужна модель регулировщика
  с позами, `regulator` в сети уже размечен).
- Дорожные вопросы: 6 из 48 (только скорость). Остальные 42:
  обгон 19, наблюдение 11, переезд 7, автобус 2, объезд, временный объезд,
  аварийная полоса. Для каждого вида — свой сценарий на прямой
  (`road_event.gd`): разметка 1.1/1.5/1.11, встречные машины, шлагбаум
  и светофор переезда, автобусный карман (`busBaySide` из game.js), трамвайные
  пути (`tramTracks`).
- Тупик (знак 6.8.x, `deadEnd`).
- Погода: дождь, снег, туман (в старой `setWeather`); сезоны есть.

### 2.7 Правила и нарушения
- Сверить список нарушений со старой игрой: встречка, одностороннее против
  движения, сплошная, скорость, пешеход, приоритет, красный, стоп-линия,
  переезд, столкновение, бездорожье, ремонт. В новой есть все строки; проверить,
  что каждое реально срабатывает (тест на каждое — `tests/rules_check.gd`).
- Смена полосы (`lane_changed`), выбор выезда (`exit_choice`, разворот).

### 2.8 Звук, вибрация, настройки
- Вибрация на ответах и ударах — через `Input.vibrate_handheld` (проверить
  разрешение в Android).
- Настройка «Звук» из приложения → аргумент `--mute`.
- Скрытое меню разработчика (погода, сезон, уровень качества, счётчик) — в
  dev-сборке долгим нажатием на паузу.

### 2.9 Аналитика и рейтинг
- Сделано: очки в рейтинг, рекорд.
- Нет: `telemetry`, `UsageReporter` по событиям игры, `perf` в logcat
  (`[game-perf]`). **Как:** `PddHost.send` всех событий + пересылка во Flutter
  после выхода или сразу через `MethodChannel` из процесса `:game` нельзя —
  писать в файл и читать при возврате.

## 3. Качество и производительность
- Профили качества low/mid/high проверить на слабом устройстве (эмуляция low).
- Время запуска экрана игры (холодный старт процесса `:game`) — цель < 3 с,
  заставка с цветом фона приложения.
- Память: сцены грузить по одной (сейчас все GLB в пакете, загрузка по
  требованию — проверить пик).
