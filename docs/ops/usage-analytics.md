# Использование режимов приложения

В «Аналитике» админки блок «Использование режимов» сравнивает билеты, темы,
экзамен, 3D-игру и ленту за выбранный период. В компактной таблице — запуски,
активные установки (уникальные за период), запуски на установку и доля
запусков. Динамика по дням свёрнута; нажатие на режим раскрывает его график.
Без событий вместо таблицы с нулями показывается пояснение о начале сбора.

Событие — открытие конкретного билета/темы, экрана экзамена или ленты, либо
начало нового заезда в 3D-игре. Открытие гаража и возврат к приостановленному
заезду не считаются. Продолжение сохранённой тренировки/экзамена считается
отдельным запуском. Работа над ошибками и избранное не приписываются билетам
или темам. Мини-игры из отдельного раздела «Игры» не входят в «3D-игру».

Уникальность считается по установке, включая гостей: человек на двух
устройствах — две установки. Период использует объединение идентификаторов,
поэтому ежедневные уникальные установки не складываются. Сервер хранит
SHA-256 идентификатора установки (первые 128 бит); админский API отдаёт только
агрегаты, без идентификаторов. Дни — по Москве.

Сбор доступен с 8 октября 2026 года и требует обновлённого приложения.
Исторические открытия до внедрения восстановить нельзя. Старые магазинные
сборки событий не отправляют; для Android/iOS нужен выпуск обновления.
Декларации данных магазинов при выпуске должны отражать сбор взаимодействий
с приложением для аналитики, помимо уже используемых идентификаторов.

`UsageReporter` сохраняет до 500 последних запусков локально, до 89 дней.
Отправка пакетами по 50 событий, повтор при старте приложения, возврате из
фона или следующем запуске режима. Оффлайн-события сохраняют исходную дату.
Ошибка сети не мешает обучению. Очень длительная работа без связи может
привести к потере событий сверх этого лимита.

`POST /api/usage` требует действующий `x-install-secret`, без прохода для
старых сборок. Сервер ждёт приёма событий в `StatsBuffer`, который убирает
повторы по ID события. Счётчики пишутся через `trackStats` в существующие
`day:*` при пакетном сбросе; дополнительных KV-записей на каждый запуск нет.
Новые события не попадают в покупки, Telegram и ленту событий админки.

Проверки: `npm run test:usage` в `server/install-notifier/`,
`flutter test test/usage_reporter_test.dart test/install_reporter_test.dart`.
