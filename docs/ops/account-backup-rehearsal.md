# Защищённая копия аккаунтов и закрытая репетиция восстановления

Подготовка к переезду на `pdd-drive.app`, 19.10.2026. Этот шаг не выпускает
воркер, не переключает домены и не меняет Platega. Оплата, callback и возврат
сохраняются на `.ru`.

## Что подготовлено

- `server/install-notifier/durable_backup.js`: чтение полного сырого состояния
  одного Durable Object внутри транзакции, включая все страницы, chunks и alarm.
  Подключён к девяти существующим DO-классам, до бизнес-обработчиков. Чтение не
  импортирует KV, не продлевает срок, не удаляет истёкшие записи и не запускает
  фоновые эффекты.
- `tools/domain_migration/secure_export.mjs`: сборщик только для числового
  loopback (`127.0.0.1` / `[::1]`, HTTP, без редиректов). Production URL он
  отклоняет. Ответы и итоговый архив шифруются RSA-OAEP-256 + AES-256-GCM (JWE).
  Незашифрованные файлы аккаунтов на диск не записываются.
- `tools/domain_migration/closed_restore.mjs`: проверка инвентаря и восстановление
  только в созданный модулем локальный реестр в памяти. Произвольный namespace,
  KV или объект с похожим API не принимается. Production restore API отсутствует.
- Тестовые аккаунты, даты, чеки, сессии и статусы — искусственные. Тесты вызывают
  реальные обработчики приложения с изолированными хранилищами. Сеть запрещена;
  ответы платёжного провайдера в callback-тестах заменяет локальная заглушка.

В snapshot попадают аккаунты, все четыре источника Премиума, большой прогресс
A/B и C/D, владельцы покупок, журнал платежей и индексы, поколения и отзывы
сессий, приватные Apple credentials, tombstones удалённых аккаунтов, outbox и
состояние остальных DO. Это чувствительные данные даже при наличии шифрования.
В отдельный подписанный раздел пакета входят **байты** KV, metadata и исходный
абсолютный expiration (Unix seconds); TTL при восстановлении не продлевается.

## Защита

Экспорт по умолчанию выключен. Внутренний путь DO `/_backup/v1/export` не
проброшен через публичный `worker.js`. Включение в будущем требует отдельного
выпуска кода и явной настройки всех условий:

- `DURABLE_BACKUP_ENABLED=true`;
- `DURABLE_BACKUP_UNTIL`: абсолютный срок в будущем, не далее одного часа;
- `DURABLE_BACKUP_HMAC_SECRET`: случайные ≥32 байта в base64url, без значения
  по умолчанию;
- `DURABLE_BACKUP_NAMESPACE_IDS`: JSON с точными namespace ID по классам;
- `DURABLE_BACKUP_SOURCE_VERSION`: проверяемая версия источника.

Подпись запроса связывает метод, путь, точное тело, namespace/object ID, класс,
run ID, версию, `ACCOUNT_STATE_EPOCH`, время, nonce и публичный ключ получателя.
Окно запроса — 60 секунд. Ответ имеет отдельный HMAC, связанный с nonce и
шифротекстом; сборщик проверяет его до расшифровки. Повтор подписанного запроса
в этом окне разрешён, но остаётся операцией чтения и шифрует тому же получателю.
Приватный ключ получателя серверу не передаётся.

SHA-256 проверяет снимки, а обязательный HMAC подписывает состав пакета вместе
с KV и provenance. Отсутствующие/повторённые объекты, неверные chunks, подмена
данных, версии или эпохи отклоняются до публикации восстановленного состояния.
Файлы ключей и архива создаются с mode 600 без перезаписи существующих файлов.
Ключ нужно сохранять отдельно от архива и не включать в его содержимое.

Alarms и отложенные задания сохраняются как свидетельства, но на стенде не
исполняются. Это исключает рассылки, повторные платежи, обращения к Apple и
запись проекций в рабочий KV. Реестр выдаёт только копии исходного состояния.

## Запуск проверок

Из корня проекта (предварительно `npm ci --ignore-scripts` в
`server/install-notifier`, Node.js с WebCrypto):

```bash
node --test server/install-notifier/test-durable-backup.mjs \
  server/install-notifier/test-backup-boundaries.mjs \
  server/install-notifier/test-backup-recovery.mjs \
  tools/domain_migration/test_closed_restore.mjs \
  tools/domain_migration/test_secure_export.mjs
```

`test_backup_runtime.mjs` дополнительно использует Miniflare/workerd с SQLite:
модульный каталог передаётся через `PDD_MINIFLARE_MODULE_ROOT` (каталог
`node_modules`, содержащий `miniflare` и `esbuild`). Процесс локальный,
исходящие соединения запрещены; конфигурация и хранилище production не нужны.

```bash
PDD_MINIFLARE_MODULE_ROOT=/absolute/path/to/node_modules \
  node --test tools/domain_migration/test_backup_runtime.mjs
```

Для локального сборщика:

```bash
node tools/domain_migration/secure_export.mjs init secrets/closed-export.key.json
node tools/domain_migration/secure_export.mjs collect \
  output/closed-plan.json secrets/closed-export.key.json \
  http://127.0.0.1:PORT/_backup/v1/export output/closed-backup.pddjwe
node tools/domain_migration/secure_export.mjs verify \
  output/closed-backup.pddjwe secrets/closed-export.key.json
```

План (mode 600) содержит `expectedObjects` — массив
`{className, namespaceId, objectId}`, `sourceVersion`, `accountEpoch`, необязательные
`runId` (UUID) и `kvEntries`. KV entry: `{key, valueBase64, expiration, metadata}`.
Сборщик не создаёт сервер и не имеет средств его публикации. Команда `verify`
выводит только суммарные числа, без аккаунтов, ключей и платёжных идентификаторов.

## Что ещё необходимо до настоящего переезда

Эта проверка **не доказывает**, что все реальные аккаунты уже сохранены.
Рабочий сервер пока не изменялся; полного экспорта содержимого production DO
этот шаг не выполняет. Прежняя копия KV не заменяет авторитетные DO и приватные
записи, которых нет в проекциях.

1. Отдельно согласовать выпуск выключенного экспортёра и защищённый канал
   доступа без публичного маршрута; после сборки закрыть окно и отозвать ключ.
2. Получить независимый полный инвентарь всех девяти namespace, включая удалённые
   и ещё не спроецированные аккаунты. Простого списка `user:*` недостаточно.
   Сохранить исходные object ID; восстанавливать имя из ID нельзя. Для новых
   namespace отдельно нужна проверенная карта логических имён и маршрутизации.
3. Собрать KV и DO с одинаковыми версией и эпохой. Каждый DO атомарен отдельно;
   общего момента времени для нескольких DO и KV нет. Нужны окно согласования
   изменений, повторная сверка журналов/владельцев платежей и проверка полноты.
   Текущие стендовые пакеты явно помечены `inventoryComplete:false` и
   `globalAtomic:false`.
4. Восстановить **настоящую** копию в отдельно закрытой среде без рабочих ключей,
   сетевых действий, cron и alarms; сверить пользователей, точные сроки каждого
   entitlement, прогресс, claims, журнал, pending/unknown/refund и tombstones.
5. Отдельно решить перенос браузерного локального прогресса и повторный вход:
   браузеры разделяют данные `.ru` и `.app`. Данный экспорт покрывает серверное
   состояние и не переносит localStorage между доменами автоматически.

До этих проверок основной домен и обработчики Platega остаются на `.ru`.
