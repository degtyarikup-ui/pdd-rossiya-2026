# Ошибки входа, покупок и поддержки — 08.11.2026

Источник: выгрузка `pdd-errors-sutki-2026-11-08.csv`, 43 события. Из них
30 относятся к версиям 2.2.8/2.2.10, 4 — к dev-сборкам 2.2.11 с временным
номером сборки, 9 — к 2.2.11+74. Время получения события не всегда совпадает
со временем ошибки; количество строк не равно количеству пострадавших людей.
Персональные данные и исходная выгрузка в репозиторий не включены.

## Установленные причины и ограничения

- Поздний успешный вход во время закрытия листа мог повторно вызвать `pop`
  и закрыть нижний экран: `mounted` остаётся true во время обратной анимации.
  Регрессионный тест воспроизводит второй `pop` на исходном коде.
- После HTTP 503/504 проверки покупки клиент оставлял чек в очереди, но
  немедленно не сверял уже выданный доступ. Сетевые исключения такую сверку
  уже запускали. Неполный успешный ответ статуса также мог снять доступ или
  ошибочно трактовать отсутствующий срок как бессрочный.
- Отправка поддержки ожидала 8+12 секунд и автоматически повторяла POST.
  Сервер мог ещё отправлять первое сообщение: первый контакт с фото и длинной
  подписью включает несколько последовательных обращений к Telegram.
  Ошибки Telegram и ответа хранилища могли неверно трактоваться как успех.
- Ошибка загрузки баннера после закрытия профиля уходила в общий обработчик
  Flutter, хотя виджет имел обработчик ошибок. Это воспроизведено тестом.
  Все 20 записей `network:http` без стека нельзя доказательно приписать этому
  сценарию. Новые отчёты различают загрузку изображений (`framework_image`)
  и остальные ошибки Flutter; адреса изображений не записываются.
- Google Play API подтвердил оба существующих productId и ACTIVE base plans.
  Все 174 настроенных региона и otherRegions разрешают новые подписки.
  Это не гарантирует доступность Billing конкретному устройству или аккаунту.
  Идентификаторы и региональные правила оплаты не менялись.
- По сохранённой транзакции единственного `premium.verify timeout` App Store
  Server API вернул Production / BILLING_RETRY, оплаченный период закончился
  04.11.2026 в 18:59 МСК. Новое подтверждённое продление не обнаружено.
  Сроки и финансовые записи аккаунта не изменялись.
- Google SDK timeout/network_error и Apple unknown сами по себе не доказывают
  ошибку backend. Старые сбои Telegram уже покрыты протоколом v2 в 2.2.11.

## Исправления 2.2.12 (75)

- Лист входа отмечает завершённое закрытие через `PopScope`; поздний ответ
  не закрывает нижний маршрут и не показывает уведомление из закрытого листа.
- Временный HTTP-отказ проверки чека запускает сверку аккаунта. Сам чек
  остаётся неподтверждённым до успешного ответа проверки; магазинная транзакция
  не завершается по одному только активному статусу Premium.
- Статус Premium принимается только с корректными типами и сроком; для
  бессрочного доступа требуется явный `premiumExpiresAt: null`.
- Поддержка отправляет POST один раз на последний рабочий адрес, с ограничением
  40 секунд для текста и 60 секунд для фото. Повтор после неопределённого исхода
  больше не выполняется автоматически. Это не гарантия exactly-once доставки
  при ручном повторе или со старого клиента.
- Сервер проверяет подтверждение Telegram и запись истории; объединяет
  карточку знакомства с коротким первым текстом, сокращая сетевые ожидания.
  Ошибка вспомогательного обновления метаданных после сохранения не превращает
  доставленное сообщение в неуспешное.
- Баннер обрабатывает поздний отказ загрузки после удаления своего listener.
