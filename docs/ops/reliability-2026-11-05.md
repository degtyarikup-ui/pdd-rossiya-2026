# Надёжность входа, покупок и ошибок — 05.11.2026

## Разбор выгрузки

CSV содержит 32 события; 26 предшествуют сегодняшнему security deploy.
Два `auth.recovered/fallback_ok` — успешное восстановление, не отказ.
У шести свежих событий нет HTTP-статуса; точные причины исторических
`apple_unknown`, Google timeout и Telegram StateError по ним не доказаны.
Поэтому исправления ниже закрывают воспроизводимые слабые места, но не
выдаются за установленную причину каждого исторического события.

## Проверки

- Flutter: 1130 успешно, 4 пропущено; анализатор без замечаний.
- Полный серверный набор: 835 тестов, 832 успешно, 3 opt-in пропущены;
  дополнительный тест старого Telegram обмена пройден после этого запуска.
- Реальный SQLite/workerd: отдельный тест Telegram проходит, сохранённый JWT
  переживает остановку процесса, неверный verifier получает 403.
- Общий opt-in AccountState runtime прошёл сохранение прогресса/Premium и restart,
  но остановился на старой инъекции SQLITE_NOMEM: текущий runtime выполняет SQL
  успешно (200 вместо ожидаемого 503). Проверку не ослабляли, AccountState не
  меняли; это ограничение этого прогона, не доказательство memory-recovery.
- Набор UI админки запущен с установленными Playwright и pngjs; прошёл.

## На что опирались

[Google Play: обработка BillingResult](https://developer.android.com/google/play/billing/errors):
отличать временные ошибки от ошибок настройки, ограничивать число повторов.
[Stripe: идемпотентность](https://stripe.com/blog/idempotency): безопасное
восстановление неопределённого результата через сохранённый результат операции.
[Apple: ошибки Sign in with Apple](https://developer.apple.com/documentation/technotes/tn3107-resolving-sign-in-with-apple-response-errors):
разделять ошибки авторизации и серверной проверки, не считать unknown диагнозом.

## Граница результата

Нельзя гарантировать доступность Apple, Google, Telegram и связи на устройстве.
Исторические SDK-сбои без точной причины остаются неподтверждёнными; новые
диагностические поля и обновлённый клиент нужны для следующего наблюдения.
Нативные изменения подготовлены в 2.2.11 (74); магазины требуют нового выпуска.
Выкладка нативной версии владельцем сохраняется согласно его инструкции.
