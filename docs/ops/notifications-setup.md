# Уведомления из админки

Экран: `/admin#notifications`. Сервер уже развёрнут, отдельное хранилище
`NOTIFICATIONS / NotificationsState`, миграция `v4-notifications`.

## Что реализовано

- Общие переключатели: пуши, всплывающие окна, серия занятий, восстановление заездов.
- Кастомный заголовок и текст; страна RU/BY/RS или все; iOS/Android/веб.
- Предпросмотр, подтверждение публикации, срок показа 1–30 дней, история и отключение.
- Окна: один показ на установку, только главная вкладка, без прерывания игры,
  экзамена или другого модального окна. Нет устаревших окон из офлайн-кэша.
- Пуши: FCM HTTP v1, отдельная durable-очередь, идемпотентный ID публикации.
  Неизвестный исход сетевого запроса не запускает повторную массовую отправку.
  «Принят Firebase» — подтверждение сервиса, не каждого устройства.
- Новостные пуши выключены у пользователя по умолчанию. В новой сборке есть
  отдельный переключатель в настройках. Firebase Messaging auto-init выключен.
- Покупки/выдача Premium и соответствующие служебные диалоги остаются независимыми.

Все изменения работают только в новой версии приложения. Магазинная 2.1.8+47
не получает кастомные окна/пуши и не читает новые переключатели.

## Подключение FCM

Создан проект `pdd-drive-notifications`, Spark (бесплатный), Google Analytics
не включён. Зарегистрированы RU Android `ru.pdd.pdd_app` и iOS `ru.pdd.pddApp`.
Клиентские конфигурации сохранены в игнорируемом `secrets/firebase/`.

Подключён отдельный аккаунт
`pdd-push-sender@pdd-drive-notifications.iam.gserviceaccount.com`, единственная
выданная роль — `roles/firebasecloudmessaging.admin`. Приватный JSON сохранён
в игнорируемом `secrets/firebase/fcm-sender.json` (права `600`) и загружен
в секрет Cloudflare `FCM_SERVICE_ACCOUNT`. В публичный репозиторий не попадает.

FCM HTTP v1 проверен 04.10.2026 через реальный подписанный запрос с
`validate_only: true`: проверка успешна, сообщений пользователям не отправлено.
Продакшен API подтвердил `pushConfigured: true`, прежние настройки сохранены,
история кампаний пуста. Общий переключатель пушей пока выключен до завершения
настройки APNs. Его включение не подписывает старые версии и пользователей
без согласия.

Темы: `pdd_mobile` и `pdd_<country>_<platform>`; приложение подписывается
только после согласия пользователя и при включённом серверном переключателе.
Email, имя и регион пользователей в Firebase для таргетинга не отправляются.

## iOS

Apple Developer запросил повторный вход владельца аккаунта. После входа
нужно включить Push Notifications для существующего App ID в Apple Developer,
создать APNs authentication key и загрузить в Firebase Cloud Messaging (Key ID,
Team ID и файл `.p8`). Ключ оплаты App Store **не подходит** для APNs.

После этого обновить provisioning profile и включить Push Notifications в
целевом Runner (entitlement `aps-environment`); для обычных видимых пушей
используется системная доставка APNs. В текущие entitlement не добавлена
неподдерживаемая возможность, чтобы не сломать существующую подпись.

## Сборка

`scripts/build.sh` автоматически подхватывает
`secrets/firebase/<country>.defines.json` для Android. Этот файл содержит
публичные клиентские идентификаторы, а не приватный ключ отправки.
Отсутствие файла оставляет пуши выключенными; окна и удалённая политика работают.

Для iOS параметры передаются при сборке:
`flutter build ipa --dart-define=COUNTRY=ru --dart-define-from-file=secrets/firebase/ru.defines.json`.
Для BY/RS перед включением SDK зарегистрировать соответствующие приложения
в Firebase и подготовить свои файлы параметров; идентификаторы RU не переиспользовать.

Перед магазинным релизом с активными пушами дополнить политику Firebase/FCM,
описанием идентификатора установки и токена доставки; проверить App Privacy и
Data Safety относительно фактически включённых функций. Новая версия пока
не отправлена на публикацию в магазины.

## Проверки

`node --test server/install-notifier/test-notifications.mjs`:
валидация, защита админки, аудитории, отключение, идемпотентность,
неизвестная доставка, подписанная авторизация FCM, immutable response headers.

`flutter test test/remote_notifications_test.dart test/notification_reminder_test.dart test/exam_flow_test.dart`:
однократный показ после перезапуска, срок, офлайн-политика, совмещение запросов,
напоминания и экзамены. `flutter analyze` изменённых файлов без замечаний.

## Форматы и оформление (админка → «Уведомления»)

| Формат | Где | Лимит текста |
|---|---|---|
| Окно (`popup`) | модальное окно на главной, 1 показ на устройство | 1000 |
| Баннер (`banner`) | карточка сверху главной, закрывается крестиком навсегда | 200 |
| Пуш (`push`) | системное уведомление FCM; опция «дублировать окном» | 300 |

Оформление: эмодзи, картинка (загрузка в KV `ntimg:<uuid>` до 1 МБ или https-ссылка,
отдаётся по `/api/notifications/image/<uuid>`), цвет акцента, макет окна
(`standard` / `compact` / `cover`), текст кнопки, вторая кнопка, действие по нажатию
(`url`, `tickets`, `topics`, `game`, `feed`, `settings`), отложенный старт (до 30 дней).

Картинка в пуше: Android — всегда (FCM `notification.image`); iOS — нужен
Notification Service Extension в Xcode (payload уже содержит `mutable-content: 1`
и `fcm_options.image`). В foreground приложение само скачивает картинку и показывает
её через flutter_local_notifications (BigPicture / attachment).
