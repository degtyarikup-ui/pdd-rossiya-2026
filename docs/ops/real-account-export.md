# Реальный экспорт аккаунтов без переключения сайта

Инструменты дополняют [локальную репетицию](account-backup-rehearsal.md).
Операторский сбор не запускается автоматически при деплое или запуске тестов.
Сайт, DNS и Platega остаются на прежних адресах.

## Источник и временный доступ

Перед вмешательством сохраняются реально опубликованные модули, настройки,
версия, имена секретов, расписания и домены Worker. API не раскрывает значения
рабочих секретов; они сохраняются Cloudflare через `keep_bindings`.
`production_export_control.mjs` формирует multipart upload, сохраняя исходные
модули байт-в-байт. `production_backup_wrapper.mjs` добавляет отдельный main:
обычные запросы и alarms выполняются исходным кодом, резервный запрос к DO
использует read-only exporter и исходную очередь `serial()`.

Временный брокер содержит только внешние DO bindings к исходным девяти классам.
У него нет KV, платёжных ключей, cron, restore или бизнес-обработчиков. Его
случайный `workers.dev` адрес принимает только подписанный запрос ограниченного
run ID и временного окна, возвращает только JWE + HMAC ответа. Неподписанный
запрос получает общий 404 до обращения к хранилищам. Логирование брокера выключено.
Рабочий публичный Worker не получает маршрута экспорта.

`collect_real_objects.mjs` принимает только точный временный HTTPS endpoint
этого аккаунта/run; исходный loopback-only сборщик не ослабляется. Локальные
контрольные точки зашифрованы и подписаны HMAC. Они проверяются до возобновления,
включая namespace/object ID, класс, run, версию и `ACCOUNT_STATE_EPOCH`.

Перед upload повторно проверяются версия, хеши модулей, настройки, отсутствие
резервных имён bindings и свободное имя брокера. Во время cleanup принадлежность
временного выпуска проверяется по точным модулям, run ID и настройкам: чужой
параллельный выпуск не перезаписывается. Удаление брокера выполняется независимо
от результата возврата исходного Worker. После возврата сравниваются модули,
настройки, расписания и домены, удаляется временный секрет.

Брокер проверяется до изменения исходного Worker: недостаточно любого HTTP 404,
нужен ожидаемый JSON-ответ его обработчика. Новый `workers.dev` адрес может
появиться на узлах не сразу. После этой проверки версия/модули/настройки источника
сверяются повторно, затем включается адаптер.

Активный deployment ID и эталонная версия содержимого учитываются отдельно.
Возврат идентичных модулей создаёт новый deployment ID. Возобновлять один run
по прежним контрольным точкам можно только после подтверждения побайтного
совпадения всех исходных модулей и эпохи с эталоном. При изменении содержимого
начинается новый сбор; готовые snapshots не переименовываются и не переподписываются
под другую версию. Интервал всех использованных snapshots сохраняется в отчёте.

## Полнота и согласованность

- Все объекты всех девяти namespace перечисляются через Cloudflare API с
  пагинацией. Учитываются также пустые объекты и удалённые аккаунты.
- После выгрузки перечисление повторяется, новые объекты включаются в копию.
  Полнота относится к объединению проверенных списков за указанный интервал,
  а не к будущим изменениям работающего сайта.
- `real_kv_export.mjs` читает все ключи KV и повторяет список, захватывает новые
  ключи; бинарные значения сохраняет без перекодирования. Значения, metadata,
  абсолютные сроки и сами имена ключей шифруются до записи на диск.
- Итоговый пакет содержит подписанный инвентарь, snapshots и KV.
  `provenance.kind=collected-nonatomic`, `globalAtomic=false`. Интервалы KV и DO
  фиксируются отдельно. Общей транзакции между ними нет; работа сайта и оплаты
  не останавливается. Несогласованные ссылки отражаются отдельными счётчиками.

## Закрытое восстановление

`validate_real_restore.mjs` расшифровывает архив только в память, проверяет HMAC,
весь состав и хеши, восстанавливает все значения в локальный реестр и настоящий
SQLite/workerd. Используются новые локальные surrogate ID; исходные ID остаются
метаданными, не подставляются в другое production namespace.

Для реальных данных обязателен приватный `storageRoot` на защищённом томе.
Операционный запуск использует зашифрованный AES-256 локальный образ. Временный
SQLite удаляется после `dispose()` в `finally`, затем том отключается. У стенда
нет production bindings/секретов, бизнес-обработчиков и cron; сеть запрещена,
alarms не устанавливаются, outbox не исполняется. Данные KV также проходят
SQLite с побайтной сверкой, сохраняя metadata и абсолютный expiration.

Отчёт содержит только агрегаты: профили, Премиум по источникам, прогресс,
платёжные статусы/журналы, владельцев чеков, удаления, поколения сессий и очереди.
В отчёте и stdout отсутствуют пользовательские идентификаторы, почта, чеки,
токены и имена ключей. Копии архива и приватного ключа хранятся раздельно;
ничего из `output/` и `secrets/` не коммитится.

```bash
PDD_MINIFLARE_MODULE_ROOT=/absolute/runtime/node_modules \
  node --test tools/domain_migration/test_real_kv_export.mjs \
  tools/domain_migration/test_real_object_export.mjs \
  tools/domain_migration/test_production_backup_wrapper.mjs \
  tools/domain_migration/test_validate_real_restore.mjs

node --max-old-space-size=8192 tools/domain_migration/validate_real_restore.mjs \
  ARCHIVE PRIVATE_KEY RUNTIME_NODE_MODULES AGGREGATE_REPORT PRIVATE_STORAGE_ROOT
```

Тест `test_production_backup_wrapper_runtime.mjs` дополнительно проверяет
адаптер на частной копии опубликованного кода; пути задаются переменными
`PDD_BACKUP_BASELINE_DIR` и `PDD_MINIFLARE_MODULE_ROOT`. Файлы источника в Git
не включаются. Полный браузерный локальный прогресс гостей, перенос OAuth на
новый домен и маршрутизация в новых namespace остаются отдельными этапами.
