# Сервер Cloudflare Worker

Рабочий код — `server/install-notifier/`. Название историческое: сейчас сервер
обслуживает аккаунты, Premium, оплаты, прогресс, игру, аналитику и админку.
Установка и эксплуатация — [README воркера](../../server/install-notifier/README.md).
Лимиты тарифа $5, измерения и сокращение операций KV/DO —
[стоимость Cloudflare](cloudflare-costs.md).
Разбор ошибок входа/магазинов/синхронизации и условия безопасного выпуска —
[аудит надёжности 22.10.2026](../ops/reliability-audit-2026-10-22.md).
Свежий разбор `SQLITE_NOMEM`, перегрузки статистики и ошибок соединения —
[аудит 24.10.2026](../ops/reliability-audit-2026-10-24.md).
Причины архитектурных отказов, воспроизводимые эксперименты и план перехода
на подтверждаемую синхронизацию и независимое хранилище —
[исследование надёжности](../ops/reliability-redesign-2026-10-24.md).

Перед изменением входа/оплаты прочитать [Premium](../premium/README.md) целиком.
Сроки изменять через `setEntitlement`/`extendEntitlement`. Статистику событий
писать через `trackStats`, чтобы не создавать KV-запись на каждый запрос.
Секреты задаются через `wrangler secret put`; значения не писать в код и документацию.

AccountState подтверждает профиль, прогресс, Premium и финансовый журнал
после основной транзакции DO. Recovery alarm сохраняется до commit; KV,
email-индекс, Telegram и статистика доставляются отдельно, обычно с
пакетированием 65 секунд. Списки админки могут отставать; статус и прогресс
конкретного аккаунта читаются из авторитетного DO. Отказ проекции не должен
срывать уже сохранённую пользовательскую операцию. Перед созданием СБП-платежа
остаётся синхронный checkpoint резерва и payment-directory, без ожидания
остальных проекций. Проверки — `npm run test:accounts`, `npm run test:storage`,
`npm run test:security` и настоящий SQLite/workerd `RUN_RUNTIME_SMOKE=1 npm run test:runtime`.

Безопасные повторы DO отмечаются только в серверном журнале событием
`durable_request_retry`: разрешённое имя операции, исход, число попыток,
длительность, HTTP-статус при наличии, технические флаги и строго проверенный
opaque reference Cloudflare. Возвращённый HTTP 4xx/5xx — `returned_error`,
а не восстановление. Первые успешные попытки не логируются. Событие не пишет KV
и не отправляет Telegram; токены, аккаунты, URL, исходные ошибки и профили
не включаются. Политика повторов и запрет слепого повторения записей не меняются.

Чтение чата поддержки не должно зависеть от доступности служебного KV-флага
вебхука Telegram: при его отказе опрос Telegram пропускается, сообщения читаются
из `SupportThread`. HTTP-ошибка или повреждённый ответ `/list` либо `/seed`
возвращает 503 (`support_read_unavailable`), а не успешный пустой список.
Повреждённая старая история отклоняется до её переноса в DO. Диагностика
сохраняет этап `list|seed` и HTTP-статус хранилища; исходные ошибки Cloudflare
сохраняют признаки `overloaded`/`retryable`. Эти поля доступны в Telegram и
добавлены в конец CSV, прежние столбцы сохраняют порядок. Перегрузку не
повторяем немедленно. Проверки отказов — `npm run test:support`.

## Проверки

Одинаковые диагностические инциденты группируются в Telegram на час; первое
сообщение новой группы ставится в очередь сразу, полный журнал CSV сохраняется.
Связанные серверные 5xx одного известного аккаунта (профиль, прогресс,
уведомления, чтение поддержки) объединяются за фиксированные 3 секунды в одно
сообщение: несколько уникальных заголовков, затем общий блок пользователя и
причины, технические данные и ID диагностики каждой операции. Код, HTTP-статус,
платформа/версия, устройство и общий контекст должны совпасть; разные аккаунты,
неизвестная личность, вход и оплата не объединяются. Каждое включённое событие
остаётся отдельной строкой CSV с sent=true (`coalesced` для добавленных).
Незавершённая группа сохраняется в TelegramQueue и переживает перезапуск;
окно не продлевается следующими событиями. Лимит размера сообщения разделяет
слишком большую группу без потери операций. Telegram retry_after имеет приоритет
над окном объединения. Проверки — `npm run test:logging`.
Для ошибок покупки и foreground-каталога окно остаётся 10 минут. Служебный
успех восстановления входа остаётся только в журнале. У автопостинга отдельная
часовая группировка по аккаунту и причине; регистрации, покупки и поддержка
через неё не проходят.

`SOCIAL_PUBLISHER_REQUIRED=true` требует binding `SOCIAL_PUBLISHER` и миграцию
`v8-social-publisher`. При недоступности координатора новая загрузка не
начинается. Lease живёт 15 минут; незавершённые намерения отправки остаются
после его истечения и не разрешают повторную загрузку. Подтверждённые ID
хранятся постоянно. Обновление сервера не переотправляет ролики с успешным
статусом. Проверки — `test-social-guard.mjs`.

Команды запускать из `server/install-notifier/`: `npm test`, затем нужные
`npm run test:*` из `package.json`. Базовый `npm test` не запускает все модульные
проверки. Для безопасности — `npm run test:security`, для публикаций —
`npm run test:publications`, для прогресса — `npm run test:progress`.
Полный перечень актуальных команд — `package.json`, тесты — `test-*.mjs`.

Модели разбора вопросов задаются в `ai_models.js`: основная — стабильная
`gemini-3.8-flash`, экономичная — `gemini-3.5-flash-lite`. Удалённые из меню
настройки (включая 1.5/2.5/3.6) автоматически используют основную модель.
Админка и API берут список из одного каталога; «Проверить модель» использует
выбор без сохранения для пользователей, «Применить модель» сохраняет его.
Оба запроса используют `thinkingLevel: low`, общий таймаут 9 секунд и не
передают устаревший `temperature`. При недоступности провайдера приложение
сохраняет официальный комментарий как резервное объяснение.

Цены — Standard text из [Google](https://ai.google.dev/gemini-api/docs/pricing),
проверены 21.10.2026. Для 3.8 учтён переход с $0.75/$3.75 на $1.50/$7.50 за
миллион входных/выходных токенов 01.01.2027 UTC; для Flash-Lite — $0.30/$2.50.
Размышления входят в выходные токены. Буфер считает цену по времени события,
накопленные расходы и тарифы уже поставленных в очередь старых событий сохраняются.
Проверки моделей: `npm run test:ai` (также включены в `test:security`).

`legacy/` — исторические одноразовые патчи, не рабочий способ редактирования.
Деплой — отдельная операция через `deploy.sh` или Wrangler; изменение файла
локально не меняет опубликованный Worker.

Миграция аккаунтов в DO, платёжный журнал, новые контракты и обязательные
шаги выпуска — [AccountState rollout](../premium/account-state-rollout.md).
После включения DO нельзя откатываться на старую запись аккаунтов в KV.
Обычный rollback — только предыдущая DO-authoritative версия с прежней эпохой.
KV-only переход требует отдельного дренирования outbox, снимка и сверки;
устаревшая KV-проекция не может перезаписывать подтверждённый прогресс или Premium.


Жалобы на вопросы: `report_questions.js` определяет подпись источника.
Flutter передаёт `source=training|game`; старый `mode=city` распознаётся
как «Игра „Живой город“» уже на сервере, без новой сборки. Другие непустые
`mode` старых клиентов — названия экранов обучения. Без контекста источник
показывается как «Не указан»: по `ticket_*` отличать игру от обучения нельзя.
Подпись выводится сразу под заголовком жалобы, режим обучения — отдельно
рядом с билетом. Проверки — `npm run test:reports` и
`test/question_report_service_test.dart`.

Instagram проверяется короткими заходами: не более двух чтений контейнера,
с ожиданием 5 секунд только между ними. Долгое кодирование оставляет статус
`processing`; следующий крон продолжает тот же контейнер. Это сохраняет время
на запись `media_publish` и освобождение lease в пределах 30-секундного
`waitUntil`, вместо прежнего ожидания до 200 секунд внутри одного запроса.
