# Стоимость Cloudflare: проверка 22.10.2026, обновление 24.10.2026

Workers Paid — минимум $5/месяц, а не предел расходов. По счёту за цикл
22.09–21.10: $5 база + $5 за записи KV + $0.15 за запросы Durable Objects.
Порог KV — 1 млн записанных ключей за цикл; пакетный REST-запрос не уменьшает
число оплачиваемых ключей. SQLite-записи внутри DO относятся к другому лимиту
(50 млн строк), это не Workers KV.

## Что изменено

- Каждый изменённый ответ сразу транзакционно сохраняется в AccountState.
  С 24.10 KV-проекция выполняется отдельным recovery alarm: обычно через
  65 секунд от первой ожидающей записи. Новые изменения до отправки заменяют
  ожидающую версию документа. При отказе KV доставка повторяется; 65 секунд
  не являются максимальной задержкой восстановления.
- Прогресс, Premium, финансовый журнал и отзыв сессий подтверждаются в DO,
  поэтому другой запрос/устройство сразу читает подтверждённое состояние.
  KV-списки админки, email-индекс и служебные отчёты могут отставать. Перезапуск
  сохраняет основные документы и durable outbox; пользовательский ответ
  не зависит от завершения проекции, Telegram и статистики.
- Сопутствующий профиль при progress/sync записывается при изменении версии,
  платформы, календарного дня активности либо раз в 5 минут для lastSeenAt.
  Покупки, выдачи/отзывы Premium и удаления немедленно сохраняются в DO.
- Одинаковый прогресс не переписывается ради updatedAt/lastSeenAt; heartbeat
  неизменившегося документа — не чаще раза в 5 минут. Обратный ответ всё равно
  содержит актуальный объединённый прогресс.
- Индекс user_email не перезаписывается, если уже указывает на этот аккаунт.
- Внешний Worker проверяет подпись/срок сессии для выбора AccountState;
  авторизация, поколение сессий и индивидуальный отзыв проверяются внутри
  того же сериализованного запроса. На обычную /api/user/* операцию — один
  вызов DO вместо трёх. Для остальных маршрутов два признака отзыва читаются
  одним RPC. Кэширования разрешения доступа нет, выход/удаление действуют сразу.
- SupportThread сообщает, инициализирована ли история. Пустой ответ на since
  больше не вызывает повторный seed из KV и ещё одно чтение DO. Пустая
  legacy-история тоже инициализируется один раз. Ответы оператора не кэшируются.
- Положительный флаг установленного Telegram webhook кэшируется в экземпляре
  Worker на минуту, вместо KV-чтения при каждом опросе. Отключение webhook
  может обнаружиться на минуту позже; доставка через работающий webhook немедленная.
- Повторная проверка уже известной установки не ставит alarm для записи
  неизменённого счётчика в KV.

Регрессии: `npm run test:storage`, `npm run test:accounts` и
`npm run test:traffic`, затем `npm run test:security`. Каждый изменённый снимок
по-прежнему подтверждается в DO; несколько ожидающих проекций одного ключа
объединяются до отправки в KV. Внешнее чтение актуального профиля/прогресса
не запускает служебный flush. 100 повторов неизменённого снимка внутри
heartbeat не создают новых проекций KV.
Тесты проверяют немедленный отзыв сессии, смену платформы/версии, полночь МСК,
перезапуск, одноразовый импорт истории и чтение нового ответа поддержки без задержки.

## Бюджет и выпуск

Цель — убрать дорогой перерасход KV, сохранив текущую архитектуру. Точного
прогноза по одной синтетической нагрузке нет: после выпуска сравнить хотя бы
полные сутки, лучше три. Лимиты общие на аккаунт, считаются по платёжному циклу,
а не календарному месяцу; уже выполненные операции оптимизация не отменяет.

В Dashboard → Billing → Billable usage выбирать текущий цикл. В KV Metrics
проверять дневной темп записей <32 тыс. и чтений <320 тыс. с запасом; в DO Metrics
разделять классы и HTTP/alarm. Для $5 без доплат DO тоже должны оставаться
в пределах 1 млн запросов и 400 тыс. GB-s за цикл. Копирование запросов в DO
не делает их бесплатными.

Старые клиенты продолжают опрашивать поддержку: даже после серверных сокращений
возможны несколько оплачиваемых миллионов DO-запросов. Это по $0.15 за каждый
начатый миллион сверх первого. На текущей нагрузке разумнее принять небольшую
доплату и выпускать уже имеющийся адаптивный SupportInbox с обычным обновлением
клиента, чем переносить базу или отключать рабочий сервер ради ровно $5.
Hard cutoff, теряющий синхронизацию/оплаты, не вводится. При росте аудитории
потребуется повторная оценка; $5 не является гарантированным максимумом.

Новых bindings, миграций и секретов нет. Тариф и настройки лимитов CPU/RAM
не повышаются. Увеличение лимита CPU не устраняет `SQLITE_NOMEM`: сначала
убраны лишняя работа в критическом пути и постоянное накопление отрицательных
записей отзыва. Это не доказательство устранения всех платформенных отказов;
после выпуска нужны наблюдения ошибок, задержек проекции и фактической стоимости.
Цель — остаться близко к базовым $5 без новой подписки, а не обещать фиксированный
счёт $5: alarms, DO duration и SQLite-записи тоже входят в общую стоимость.

Полный порядок проверки/выкладки и
согласование production-деплоя — [AccountState rollout](../premium/account-state-rollout.md).
После перехода на асинхронные проекции обычный откат возможен только на
предыдущую DO-authoritative версию с той же эпохой. Исторический KV-only
откат требует отдельного дренирования outbox, согласованного снимка и сверки;
не считать KV немедленной резервной копией подтверждённых аккаунтных операций.
