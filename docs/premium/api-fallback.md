# Запасной адрес сервера (api.pdd-drive.ru)

Основной адрес воркера — `pdd-install-notifier.sergei-pdd.workers.dev`. У части
операторов маршрут до `*.workers.dev` нестабилен: вход заканчивается ошибкой
«нет связи с сервером», а отчёты об ошибках тоже не доходят (они идут туда же).
Запасной адрес — тот же воркер на нашем домене.

## Что уже сделано в приложении

- `BackendConfig.notifierHosts` = основной + `https://api.pdd-drive.ru`
  (`INSTALL_NOTIFY_FALLBACK_URL`). Запасной подключается только к боевому воркеру.
- Вход (`/api/auth/session`): три попытки по очереди — основной, запасной,
  основной (8 + 8 + 10 с). Ответ сервера не повторяется. `sendWithRetry` в
  `lib/data/services/network_retry.dart`; адрес, который сработал, пробуется первым.
- Отчёты об ошибках (`/api/diagnostics`) пробуют основной, затем запасной.
- Остальные запросы (синхронизация, оплата, рейтинг) идут на основной адрес.
- Сообщения в Telegram: `timeout:3x` — сбой связи, три попытки не помогли;
  `Вход удался не сразу` (`auth.recovered`) с кодом `retry_ok:2x` (помог повтор)
  или `fallback_ok:2x` (помог запасной адрес — значит, основной недоступен части людей).
- Пока адреса `api.pdd-drive.ru` нет в DNS, запрос к нему мгновенно завершается
  ошибкой, и приложение продолжает работать с основным адресом.

## Что нужно сделать вам (один раз, ~20 минут)

Домен `pdd-drive.ru` сейчас обслуживают серверы имён reg.ru (`ns1.reg.ru`,
`ns2.reg.ru`). Кастомный домен для воркера Cloudflare подключает только если
домен находится в Cloudflare. Сайт остаётся на GitHub Pages и работает как раньше.

Записи домена на сегодня (проверено `dig`):

| Имя | Тип | Значение |
| --- | --- | --- |
| `pdd-drive.ru` | A ×4 | 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153 |
| `www` | CNAME | degtyarikup-ui.github.io |
| `app` | CNAME | degtyarikup-ui.github.io |
| `pdd-drive.ru` | TXT | google-site-verification=gBMLyOe9Q7u2bna8S6a75xXuoNIyj04Xz5HM5cn1yBo |

Почты (MX) на домене нет.

1. Войдите в Cloudflare **тем же аккаунтом, где лежит воркер**
   (mojomaker.play@gmail.com): <https://dash.cloudflare.com/>.
2. «Add a domain» → `pdd-drive.ru` → план **Free**.
3. Cloudflare сам подтянет записи. Сверьте со списком выше. У четырёх A-записей
   и у CNAME `www` и `app` переключите оранжевое облако на серое (**DNS only**):
   сайт и HTTPS обслуживает GitHub Pages, прокси Cloudflare тут не нужен.
4. Cloudflare покажет два сервера имён вида `xxx.ns.cloudflare.com`.
   В reg.ru: <https://www.reg.ru/user/account/> → «Домены» → `pdd-drive.ru` →
   «DNS-серверы и управление зоной» → «Свои DNS-серверы» → впишите два адреса
   Cloudflare и сохраните.
5. Подождите, пока Cloudflare напишет «Active» (от нескольких минут до суток).
   Всё это время сайт работает.
6. Напишите мне: я подключу домен к воркеру (см. ниже), проверю и выкачу.

Если что-то пошло не так, верните в reg.ru серверы `ns1.reg.ru` и `ns2.reg.ru`:
всё вернётся как было.

## Что делаю я, когда зона активна

В `server/install-notifier/wrangler.toml` добавить:

```toml
routes = [{ pattern = "api.pdd-drive.ru", custom_domain = true }]
```

Затем `npx wrangler deploy` в `server/install-notifier` — Cloudflare сам создаст
DNS-запись и сертификат. Проверка: `curl https://api.pdd-drive.ru/api/pay/status`
должен вернуть то же, что основной адрес. До этого строку не добавлять: деплой
воркера без зоны в аккаунте завершится ошибкой.

## Ограничения

- Если проблема у оператора не в имени `workers.dev`, а в адресах Cloudflare
  вообще, запасной адрес не поможет (тот же Cloudflare). Тогда нужен путь вне
  Cloudflare (например, пересылающая функция в Yandex Cloud) — отдельная задача.
- Запасной адрес получит только версия приложения, где это сделано (сборка после 10.10.2026).
