# Автоматизация SEO: что умеет и как этим пользоваться

Три инструмента в `tools/seo/`. Первые два работают уже сейчас, третий ждёт
разовой настройки от Сергея (5 минут, шаги ниже).

## Принцип: что автоматизируем, а что нет

Массовая генерация страниц (по городам, по каждому вопросу билета, под
низкочастотники) — **сознательно не делаем**. Google с марта 2024 бьёт за это
отдельной политикой *scaled content abuse*, и по разборам апдейтов 2026 сайты
с сотнями AI-страниц без редакторского контроля теряли 50–80% трафика.
У нас один домен, на нём же висит приложение из сторов — терять его ради
страниц-пустышек невыгодно. Все 26 официальных тем билетов уже покрыты,
так что «ещё 200 статей» = разбавление того же материала.

Автоматизируем то, что даёт качество и обратную связь:
контроль регрессий, контроль устаревания фактов, приоритизация по реальному спросу.

## 1. Регресс-аудит — `tools/seo/audit.py`

Ловит поломки, которые не видно глазом на странице, но которые стоят трафика.

```bash
python3 tools/seo/audit.py           # с предупреждениями
python3 tools/seo/audit.py --quiet   # только ошибки
```

Проверяет: валидность JSON-LD, битые внутренние ссылки и якоря словаря,
наличие/длину/уникальность `title` и `description`, `canonical`, `alt` у картинок
и существование файлов картинок, синхронность `sitemap.xml` с реальными
страницами (в обе стороны), страницы-орфаны без входящих ссылок,
вменяемость `robots.txt`, ссылки из `llms.txt` на живые страницы,
эмодзи в разметке (у нас правило — SVG-иконки).

**Встроен в деплой.** `scripts/deploy_landing.sh` запускает аудит перед публикацией
и останавливает деплой при ошибках. Обойти осознанно:

```bash
SKIP_SEO_AUDIT=1 ./scripts/deploy_landing.sh ru "..."
```

Файлы подтверждения прав (`yandex_*.html`, `google*.html`) аудит намеренно
пропускает — у них не должно быть ни `title`, ни `canonical`.
**Не удалять их с сайта: подтверждение прав слетит.**

## 2. Монитор устаревания фактов — `tools/seo/fact_watch.py`

Статьи ссылаются на суммы штрафов, статьи КоАП/УК и номера постановлений.
Законы меняются, текст — нет. Мы это уже ловили: в статье об обгоне штраф
по ч.4 ст.12.15 КоАП был 5000 ₽, хотя актуально 7500 ₽. Такая ошибка не ломает
сайт и не видна в аналитике — она просто подрывает доверие.

```bash
python3 tools/seo/fact_watch.py scan              # обновить реестр из статей
python3 tools/seo/fact_watch.py due               # что пора перепроверить
python3 tools/seo/fact_watch.py due --risk high   # только суммы и КоАП/УК
python3 tools/seo/fact_watch.py verify <id> --note "сверено с consultant.ru"
python3 tools/seo/fact_watch.py verify --all-listed
```

Сам в интернет не ходит: находит проверяемые утверждения и ведёт реестр
с датой сверки. Собственно проверку делает Claude веб-поиском по списку из `due`.

Периодичность пересверки: `high` (суммы, КоАП/УК) — 90 дней,
`medium` (номера НПА, сроки) — 180, `low` (пункты ПДД, скорости) — 365.
Низкий риск у пунктов ПДД и скоростей потому, что их нумерация стабильна,
а цифры взяты из официальной базы вопросов приложения, а не сочинены.

Реестр — `docs/fact-registry.json`, лежит в гите, чтобы история сверок не терялась.
Если утверждение отредактировали, у него меняется id и оно снова попадает в `due` —
это правильно.

**Состояние на 2026-08-13:** 216 утверждений, все 29 высокорисковых сверены
с первоисточниками.

## 3. Отчёт Search Console — `tools/seo/gsc_report.py`

Превращает данные поиска в список задач: где мы близко к топу, что ищут без
нашей страницы, что просело.

```bash
python3 tools/seo/gsc_report.py             # за 28 дней
python3 tools/seo/gsc_report.py --days 7
python3 tools/seo/gsc_report.py --json отчёт.json
```

### Разовая настройка (нужен Сергей, ~5 минут)

Google не даёт доступ к API по обычному логину — нужен «сервисный аккаунт»
(технический пользователь для скриптов).

1. Установить библиотеки:
   ```bash
   pip3 install --user google-api-python-client google-auth
   ```
2. Зайти на [console.cloud.google.com](https://console.cloud.google.com) под
   `degtyarik.up@gmail.com`, создать проект (или взять существующий —
   подойдёт тот же, где Nano Banana).
3. В поиске по консоли найти **Google Search Console API** → *Enable*.
4. **IAM & Admin → Service Accounts → Create service account**, имя любое
   (например `seo-reader`). Роль можно не назначать.
5. Открыть созданный аккаунт → вкладка **Keys → Add key → Create new key → JSON**.
   Скачается файл.
6. Положить его в репозиторий как `secrets/gsc-service-account.json`
   (каталог в `.gitignore`, ключ в гит не попадёт — проверено).
7. Скопировать e-mail сервисного аккаунта (вида
   `seo-reader@проект.iam.gserviceaccount.com`) и добавить его в
   [Search Console](https://search.google.com/search-console) →
   **Настройки → Пользователи и разрешения → Добавить пользователя**,
   роль «Полный» или «Ограниченный».

После этого `gsc_report.py` заработает. Если данных ещё нет — скрипт честно
скажет об этом: статистика появляется через день-два после подтверждения сайта,
а накапливается за пару недель.

## Что осталось нерешённым

- **Внешние ссылки** — единственный крупный фактор, который нельзя
  автоматизировать безопасно. Покупка ссылок нарушает правила Google.
  Реальные варианты: пост со ссылкой в TG-канале `@pdd_rus1`,
  карточки в каталогах приложений и отзовиках.
- **Яндекс.Вебмастер API** — есть, но у Яндекса статистика запросов
  накапливается 1–2 недели после подтверждения; вернуться к этому,
  когда появятся данные.
- **Расписание** — сейчас всё запускается вручную/через Claude. Когда
  накопится статистика GSC, имеет смысл повесить `fact_watch due` и
  `gsc_report` на регулярный запуск.
