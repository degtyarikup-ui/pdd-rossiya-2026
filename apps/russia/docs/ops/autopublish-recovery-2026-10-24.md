# Автопубликации: причины и исправление 24.10.2026

## Подтверждённая причина повторных сбоев

В 19:00 МСК сработало расписание `game_006.mp4`. Ролик содержал старые
`instagramContainerId`, `instagramMediaId`, `youtubeVideoId`, хотя статусы
обеих площадок были возвращены в очередь и `publishedAt` очищен. Снимок
22 октября показывает это же несогласованное состояние у выпусков 004–006;
первые два позднее восстановили отдельными заменами. Таким образом,
исправление одного выпуска оставляло следующий с той же причиной сбоя.

Авторизованные проверки 24 октября подтвердили аккаунт Instagram и канал
YouTube. Контейнер Instagram 006 имел статус `PUBLISHED`, но объект публикации
отвечал HTTP 400/code 100/subcode 33. Чтение списка текущих медиа работало.
YouTube videos.list успешно вернул пустой список для старого ID. Почему именно
старые записи были сняты с площадок, доступные API и журнал не устанавливают.

Старый код пытался продолжить опубликованный контейнер Instagram и требовал
ручной проверки отсутствующего media. YouTube останавливался уже на наличии
сохранённого ID, вообще не проверяя его доступность. После выставления
`instagramNeedsReview` крон исключал весь ролик из последующих запусков.
У всех 34 следующих записей на момент проверки старых ID публикаций нет.

## Дополнительные причины ненадёжного восстановления

- Все ролики менялись одним read/modify/write значением KV. У KV нет атомарных
  транзакций: конкурирующие записи могут затирать изменения, а чтение может
  вернуть старый снимок. Площадка могла принять публикацию, пока статус терялся.
- Создание контейнера Instagram сохранялось в DO, но результат `media_publish`
  сохранялся только в KV. Отдельного надёжного подтверждения финального ID не было.
- YouTube открывал resumable-сессию, но не сохранял её адрес. При потерянном
  ответе загрузки система могла лишь заблокировать повтор.
- Отказ служебного журнала мог попасть в обработчик ошибки уже успешной
  публикации. Сообщения «публиковать нечего» вытесняли реальные события из журнала.

Семантика KV подтверждена [документацией Cloudflare](https://developers.cloudflare.com/kv/concepts/how-kv-works/).
Восстановление YouTube реализовано по [официальному протоколу](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol).
HTTP `waitUntil` ограничен 30 секундами после ответа, но cron имеет до 15 минут
wall time — эти случаи нельзя смешивать. См. [лимиты Worker](https://developers.cloudflare.com/workers/platform/limits/).

## Исправление

- Очередь перенесена в SQLite существующего SocialPublisher: однократный импорт,
  записи по роликам, проверка прежних значений изменяемых полей, атомарное
  отклонение конфликтов, защита от параллельного импорта одинакового файла.
  KV — только отложенная проекция; отказ проекции не отменяет рабочее состояние.
- Наступившая явно назначенная публикация проверяет прежние ID. Доступные
  публикации восстанавливаются без отправки, недоступные архивируются и заменяются
  отдельной попыткой. Успешные площадки, будущие даты, записи без даты и неизвестные
  результаты отправки не разрешают новую загрузку.
- Финальный ответ Instagram сохраняется в DO до обновления очереди. Pending intent
  не переотправляется вслепую; возвращённый ID восстанавливается после перезапуска.
- YouTube сохраняет сессию/размер/SHA-256 до байтов и восстанавливает ответ либо
  продолжает ту же загрузку с подтверждённого смещения. Изменившийся файл,
  истёкшая неопределённая сессия и неправильный Range не создают второй upload.
- Журнал не может превратить успешную публикацию в ошибку; пустые тики больше
  не вытесняют события. Незавершённая загрузка продолжает обрабатываться кроном.

## Проверки

До выпуска: 634 серверных теста прошли; два opt-in runtime-теста пропущены в
общем запуске. Отдельная проверка нового механизма на настоящем workerd/SQLite
прошла: очередь >128 КиБ, перезапуск, атомарность конфликта, отказ KV и автоматическая
доставка alarm. Базовый npm test, UI публикаций и dry-run также прошли.
Flutter analyze без замечаний; 796 тестов прошли, три пропущены.

Сравнение исходников через source map опубликованного Worker: 92 прежних
модуля совпадают; меняются только social.js/social_guard.js и добавляются
social_queue.js/youtube_upload.js. Аккаунты, Premium, платежи и прогресс
этим выпуском не меняются. Новых сервисов, секретов, bindings и миграций нет.

После импорта очереди нельзя откатываться на старый KV-only механизм или
редактировать social:posts напрямую через KV. Для ремонта использовать admin API;
для отката требуется согласованный экспорт SQLite и отдельная сверка состояния.
Приватные снимки и логи — output/autopublish-2026-10-24/, вне Git.
