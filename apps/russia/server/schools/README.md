# Кабинет автошкол ПДД России

Первый этап работает отдельно от аккаунтов учеников и внутренней администрации. Целевой адрес кабинета — `schools.pdd-drive.app`. Для будущей публичной страницы предусмотрен путь `pdd-drive.app/avtoshkolam/`. Роутинг production этим модулем не меняется.

## Локальный запуск

Из этой директории, с Python 3.12:

```sh
export PDD_SCHOOLS_LOCAL=1
export PDD_SCHOOLS_STATE="$PWD/../../../../output/schools-local"
python3.12 -m venv "$PDD_SCHOOLS_STATE/venv"
"$PDD_SCHOOLS_STATE/venv/bin/pip" install -r requirements.txt
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py migrate
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py school_demo
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py runserver 127.0.0.1:8765
```

Откройте `http://127.0.0.1:8765/`. В локальном каталоге состояния находятся SQLite, тестовая почта в `mail/` и случайные пароли демонстрационных аккаунтов в `demo-access.txt`. При первом входе управляющий подключает приложение-аутентификатор и получает резервные коды. Для проверки новой регистрации создайте аккаунт и откройте ссылку из тестового письма. Команда демоданных идемпотентна при повторном запуске на том же каталоге. Локальный сервер привязывается к loopback.

## Что реализовано

- Подтверждённая почта, пароль, восстановление с отзывом сессий, TOTP и резервные коды через django-allauth. Включение второго фактора обязательно для управляющего.
- Создание школы, согласие с условиями тестового режима, адресные одноразовые приглашения инструкторов с перевыпуском, отзывом и сроком три дня. Приглашённый подтверждает участие. События школы записываются в `portal_event`.
- Группы, назначение преподавателя, архивирование, отключение инструктора с передачей групп управляющему. Школа и роль проверяются сервером при каждом запросе. Сотрудник с несколькими членствами переключает школу в меню.
- Ссылка и QR-код приглашения открывают только название школы, группу и преподавателя. Отзыв действует сразу. Реальное вступление и статистика из приложения, денежные события и выплаты относятся к следующим этапам. Данные списка учеников заполняет только локальная команда.

## Проверки

```sh
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py check
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py makemigrations --check
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py test portal
```

Перед реальным пилотом требуются согласованные условия, размещение базы и копий, почтовая доставка и HTTPS на целевом хосте. Вне локального режима используются SMTP с TLS, серверный секрет из окружения, host-only Secure cookies и разрешён только целевой хост. Секрет служит также для защиты ключей MFA и подписанных ссылок и должен восстанавливаться вместе с резервной копией.


## Вход через аккаунт ПДД

На входе и регистрации доступны одинаковые провайдеры. При первом входе сотрудник создаёт школу или принимает адресное приглашение. Существующий сотрудник подключает ещё один способ в настройках профиля. Совпадение адреса само по себе не связывает аккаунты. Токены приложения не сохраняются в кабинете.

| Провайдер | Подключение к целевому хосту |
| --- | --- |
| Google | Google Identity Services, серверная проверка подписанного ID token и одноразового nonce. Добавить origin `https://schools.pdd-drive.app` в Authorized JavaScript origins веб-клиента. Для другого клиента задать `PDD_SCHOOLS_GOOGLE_ID`. |
| Яндекс | OAuth с PKCE S256. Разрешить Redirect URI `https://schools.pdd-drive.app/accounts/yandex/login/callback/`. Для другого клиента задать `PDD_SCHOOLS_YANDEX_ID`. |
| Telegram | Действующий бот ПДД и протокол v2 сервера приложения. Указать `PDD_SCHOOLS_BOT_BRIDGE_FILE` с ключом серверного вызова или передать его через `PDD_SCHOOLS_BOT_BRIDGE_KEY`. В браузер уходит только ссылка на бота. При первом входе сотрудник подтверждает контактную почту. |
| Apple | Веб-вход с обменом authorization code, проверкой подписи Apple и отдельным приёмом form_post. В Services ID разрешить `https://schools.pdd-drive.app/accounts/apple/login/callback/`. Указать `PDD_SCHOOLS_APPLE_TEAM`, `PDD_SCHOOLS_APPLE_KEY_ID` и путь `PDD_SCHOOLS_APPLE_KEY_FILE` к ключу Sign in with Apple. При необходимости задать другой `PDD_SCHOOLS_APPLE_ID`. |

Файл ключа Apple относится к Sign in with Apple. Ключи подписок и App Store Connect имеют иное назначение. Параметры SMTP и секрета кабинета приведены в `portal/settings.py`. Приложение WSGI — `portal.wsgi:application`. Обслуживать статику из `collectstatic`. При недоступной почте отзыв доступа вступает в силу сразу, а команда `manage.py deliver_school_notices` повторяет недоставленные уведомления. Для реального размещения подключить её к планировщику.
