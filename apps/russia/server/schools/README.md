# Кабинет автошкол ПДД России

Кабинет работает на [schools.pdd-drive.app](https://schools.pdd-drive.app/). Сотрудник входит своим аккаунтом ПДД России или подтверждает электронную почту. Школы, роли, приглашения и второй фактор хранятся отдельно от профилей учеников.

## Локальный запуск

Из этой директории, с Python 3.12:

```sh
export PDD_SCHOOLS_LOCAL=1
export PDD_SCHOOLS_STATE="$PWD/../../../../output/schools-local"
python3.12 -m venv "$PDD_SCHOOLS_STATE/venv"
"$PDD_SCHOOLS_STATE/venv/bin/pip" install -r requirements.txt
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py migrate
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py school_demo
"$PDD_SCHOOLS_STATE/venv/bin/python" manage.py runserver 127.0.0.1:8765
```

Откройте `http://127.0.0.1:8765/`. В локальном каталоге состояния находятся SQLite, тестовая почта в `mail/` и случайные пароли демонстрационных аккаунтов в `demo-access.txt`. После создания школы открывается обзор. Приложение-аутентификатор и резервные коды можно подключить в настройках профиля. Для проверки новой регистрации создайте аккаунт и откройте ссылку из тестового письма. Команда демоданных идемпотентна при повторном запуске на том же каталоге. Локальный сервер привязывается к loopback.

## Что реализовано

- Подтверждённая почта, пароль, восстановление с отзывом сессий, TOTP и резервные коды через django-allauth. Второй фактор включается по желанию пользователя.
- Создание школы, согласие с условиями тестового режима, адресные одноразовые приглашения инструкторов с перевыпуском, отзывом и сроком три дня. Приглашённый подтверждает участие. События школы записываются в `portal_event`.
- Группы, назначение преподавателя, архивирование, отключение инструктора с передачей групп управляющему. Школа и роль проверяются сервером при каждом запросе. Сотрудник с несколькими членствами переключает школу в меню.
- Ученик открывает ссылку или QR, либо вводит код группы в «Моя автошкола». Приложение подтверждает аккаунт через свой API. Просмотр приглашения не добавляет ученика. Подтверждение записывает членство, версию согласия и атрибуцию в одной транзакции. Переход закрывает прежнее членство, выход убирает ученика из списка. Отзыв ссылки обновляет и ручной код. Денежные операции и отображение учебной статистики — отдельные этапы.
- Адрес ученика в веб-версии — [Моя автошкола](https://pdd-drive.app/app/?school_group=my). iOS Universal Links и Android App Links для новых сборок обслуживаются на домене кабинета. Авторизация учащихся использует серверную сессию ПДД, отдельную от учётных записей сотрудников.

## Вход через ПДД России

Кнопка «Войти через ПДД России» ведёт на действующий домен веб-приложения. Для Google, Яндекса, Telegram и Apple используются те же клиенты, бот и зарегистрированные адреса возврата, что и в приложении. Сотрудник подтверждает аккаунт перед переходом в кабинет. Сессия ПДД остаётся в приложении.

Кабинет хранит случайный проверочный секрет в своей сессии. После входа сервер ПДД выдаёт одноразовый код на две минуты. Обмен требует исходного секрета. Кабинет получает идентификатор провайдера и подтверждённую почту, если она есть. Для Telegram при первой регистрации потребуется подтвердить контактную почту отдельно. Дополнительный способ входа привязывается в настройках действующего аккаунта.

Локальный режим сохраняет непосредственные входы через провайдеров для автономных проверок. В опубликованном кабинете все кнопки социальных провайдеров используют общий вход.

## Размещение в Cloudflare

Worker `pdd-schools` обслуживает адрес `schools.pdd-drive.app`. Объект `SchoolPortal` с именем `schools-v1` последовательно обрабатывает запросы пилота. Django выполняет транзакции в SQLite. Перед отправкой ответа изменённые блоки базы фиксируются одной транзакцией в постоянном SQLite-хранилище объекта. После перезапуска Worker восстанавливает базу и применяет миграции. Статические файлы обслуживаются отдельно.

Cloudflare хранит историю для восстановления Durable Object за 30 дней. Секрет `PORTAL_SECRET` необходим и после восстановления для расшифровки ключей MFA. Исходная копия секрета хранится вне репозитория. Для роста числа школ и подключения статистики учеников требуется измерить нагрузку на единственный объект и размер рабочей копии базы. [Восстановление Durable Objects](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#pitr-point-in-time-recovery-api).

Письма приходят от `cabinet@schools.pdd-drive.app` через Cloudflare Email Sending. Раз в час Worker удаляет истекшие сессии и повторяет отложенные уведомления об изменениях доступа.

### Сборка и публикация

Из корня репозитория на машине с `uv`, Node.js и авторизованным Wrangler выполните следующие команды. Для первой установки передайте `--secrets-file` с закрытым JSON, содержащим `PORTAL_SECRET`. Повторная публикация сохраняет существующий секрет.

```sh
portal_source="$PWD/apps/russia/server/schools/cloudflare"
portal_build="$PWD/output/schools-worker"
mkdir -p "$portal_build"
cp "$portal_source"/{entry.py,pyproject.toml,pylock.toml,wrangler.jsonc} "$portal_build/"
(cd "$portal_build" && uvx --with 'uv>=0.13.4' --from workers-py pywrangler sync)
python3 "$portal_source/prepare.py" "$portal_build"
(cd "$portal_build" && npx wrangler deploy)
```

Общий веб-клиент поддерживает вход в кабинет при обычном релизе приложения. Для отдельной поставки школы `prepare_web.py` принимает проверенную Flutter-сборку с базой `/app/` и каталог `app` из действующей ветки `gh-pages`. Остальные посетители продолжают получать текущую версию приложения.
