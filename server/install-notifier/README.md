# pdd-install-notifier

Cloudflare Worker: приложение шлёт сюда событие о новой установке, воркер
пересылает его в Telegram-чат. **Токен бота живёт только здесь**, в приложение
не попадает. Используется Workers Paid / Standard (от $5/месяц); включены 10 млн
вызовов Worker и 1 млн записей KV в месяц, превышение оплачивается отдельно.

## Что понадобится

- Токен бота от **@BotFather** (уже есть у тебя).
- **CHAT_ID** чата/группы, куда слать. Как узнать: добавь в свой чат бота
  **@getidsbot** (или **@RawDataBot**) — он пришлёт `chat id`. Для групп id
  начинается с `-100...`.

## Самый простой способ — один скрипт

Открой Терминал и вставь одну строку:

```bash
bash server/install-notifier/deploy.sh
```

Скрипт сам поставит инструмент, создаст хранилище для номеров и опубликует воркер.
От тебя: нажать «Allow» в браузере и вставить токен бота + id чата, когда попросит.
В конце он напечатает URL воркера.

Ниже — то же самое вручную, если хочется контролировать каждый шаг.

## Деплой (один раз, ~5 минут)

```bash
# 1. Установить wrangler (нужен Node.js)
npm install -g wrangler

# 2. Войти в Cloudflare (откроется браузер, аккаунт бесплатный)
wrangler login

# 3. Задать секреты (значения не коммитятся, хранятся в Cloudflare)
cd server/install-notifier
wrangler secret put BOT_TOKEN       # вставить токен от @BotFather
wrangler secret put CHAT_ID         # id чата (напр. -1001234567890)
wrangler secret put ADMIN_PASSWORD  # пароль для входа в веб-админку /admin
wrangler secret put SHARED_SECRET   # ключ приложения (см. ниже) — обязателен

# 4. (для номера «Пользователь #N») создать KV-хранилище
wrangler kv namespace create INSTALLS
#   → напечатает id; вставить его в wrangler.toml и раскомментировать
#     блок [[kv_namespaces]] (см. комментарий в файле).
#   Без этого шага воркер работает, но вместо #N показывает install_id.

# 5. Задеплоить
wrangler deploy
```

## Веб-админка и аналитика соцсетей

После деплоя доступна панель аналитики:
```
https://pdd-install-notifier.<твой-субдомен>.workers.dev/admin
```

- **Пароль**: только значение секрета `ADMIN_PASSWORD` (`wrangler secret put ADMIN_PASSWORD`).
  Паролей по умолчанию нет: пока секрет не задан, вход закрыт для всех — исходник
  воркера лежит в публичном репозитории, и зашитый в код пароль равносилен
  открытой админке. Вход защищён от перебора (8 попыток с адреса на 15 минут),
  в куке хранится случайный токен сессии, а не пароль.
- **Метрики**: Просмотры сайта, клики по кнопкам сторов (RuStore, Google Play, App Store, Веб), новые установки и CTR / CR конверсии.
- **Соцсети**: Статистика по YouTube, TikTok, Instagram, Telegram, VK и кампаниям.
- **Генератор ссылок**: Встроен в админку — создание размеченных ссылок для Shorts, Reels, Bio в 1 клик.
- **Live Feed**: Лента переходов и установок в реальном времени.
- **Автопостинг**: Раздел публикует ролики в Instagram Reels и YouTube Shorts
  по расписанию — папка на Google Диске → очередь → один ролик в день.
  Настройка доступов и подробности — в [SOCIAL_SETUP.md](SOCIAL_SETUP.md).

Команда `wrangler deploy` в конце напечатает URL вида:

```

```

## Что где лежит

- `worker.js` — сам воркер. Разметка админки внутри него собрана экранированными
  строками: руками её не правят, раздел «Автопостинг» подключается модулями

- `legacy/` — архив одноразовых патчей воркера и админки. Не запускать: они

  (`node test-admin-local.mjs`).

## Ключ приложения (SHARED_SECRET)

### Диагностика входа

Каждый запрос `/api/auth/session` пишет событие `auth_session`: случайный
`requestId`, провайдер, HTTP-статус, этап отказа и длительность. Токены, ключи,
имена, email и идентификаторы пользователей не записываются. Ответ содержит
`x-auth-diagnostic-id`. Журналы включены в `wrangler.toml`; автоматические
журналы вызовов отключены, параметры URL скрываются.

Для разбора попросите повторить вход и указать время с часовым поясом.
События доступны в Cloudflare Workers → pdd-install-notifier → Observability
или в живом потоке `wrangler tail pdd-install-notifier --search auth_session`.
`app_key_rejected` — отказ по ключу сборки, `oauth_client_rejected` — неверный
OAuth-клиент, `provider_timeout` — таймаут провайдера, `credential_rejected` —
непринятые учётные данные, `session_issued` — сервер выдал сессию. Отсутствие
события само по себе не различает ошибку на телефоне и блокировку до Worker.

Разбор вопросов от ИИ работает через наш ключ Gemini, то есть за наши деньги.
Чтобы эндпоинт `/api/ai/chat` не превратился в бесплатный доступ к нейросети
для посторонних, приложение подписывает запросы заголовком `x-install-secret`.

- Значение лежит в `secrets/install_notify_secret.txt` (папка в `.gitignore`)
  и в секрете воркера `SHARED_SECRET`. `scripts/build.sh` подставляет его в
  сборку сам — отдельно ничего экспортировать не нужно.
- Свободный чат с ИИ доступен **только** подписанным запросам.
- Версии, выпущенные до появления ключа, подписывать нечем, поэтому им оставлен
  узкий проход: разбор конкретного вопроса, без чата, не более 40 запросов в
  сутки с адреса. Когда обновление разойдётся по магазинам — сними галочку
  «Пускать приложения без ключа» в разделе «Управление ИИ», и проход закроется.
- Тот же ключ защищает пинги об установках и жалобы на вопросы: присланный
  неверный ключ отвергается сразу.

⚠️ Если потерять `secrets/install_notify_secret.txt`, новые сборки перестанут
проходить проверку — тогда задай `SHARED_SECRET` заново и пересобери приложение.

## Подключить к приложению

**Способ 1 (рекомендуется)** — через переменные окружения, ничего не хардкодится
и не попадает в git. `scripts/build.sh` сам подставит их в сборку:

```bash
export INSTALL_NOTIFY_URL=https://pdd-install-notifier.<субдомен>.workers.dev
export INSTALL_NOTIFY_SECRET=<строка>   # только если задавал SHARED_SECRET
./scripts/build.sh ru aab
```

**Способ 2** — вписать URL прямо в код: заменить `PASTE_WORKER_URL_HERE` в поле
`defaultValue` в `lib/data/services/install_reporter.dart`.

Если ни то, ни другое не задано — фича «спит» (приложение ничего не шлёт).

## Кого трекаем

Только новых пользователей. Клиент по-прежнему шлёт `kind: 'new'|'update'`
(update — юзер, у которого уже были данные приложения до этой фичи), но воркер
события с `kind='update'` молча игнорирует: не занимают номер, не попадают в
статистику/чат. Клиент получает 2xx и просто больше не повторяет запрос.

## Что в сообщении

`🆕 Новая установка` / `🔄 Обновился` · `👤 #N` · `🏬 источник` · устройство · ОС ·
версия · язык · время. **Источник** определяется по магазину-установщику:
Google Play, RuStore, App Store, TestFlight, Web и т.п. (на sideload/APK —
«Sideload/неизвестно»).

## Ежемесячная сводка

Cron-триггер `0 6 1 * *` (1-го числа, 09:00 МСК) шлёт итоги прошедшего месяца:
сколько новых установок, обновившихся, всего и **разбивку по источникам**
(Google Play / RuStore / Web / …). Считается по помесячным ключам в KV
(`m:YYYY-MM:total|new|upd` и `m:YYYY-MM:src:<источник>`). Регистрируется
автоматически при `wrangler deploy`.

## Как приложение защищено от кражи токена

Токен бота хранится в секрете воркера и в APK не попадает — из установленного
приложения его вытащить нельзя. `SHARED_SECRET` — необязательный дополнительный
барьер против постороннего спама на эндпоинт (в клиенте он всё же присутствует,
поэтому это защита «от случайных», а не «от целевого» злоупотребления).


## Устойчивость к наплыву пользователей

`TrafficState` (binding `TRAFFIC`, миграция `v3-traffic`) последовательно
обрабатывает установки, регистрации и недельный рейтинг. При первом обращении
импортирует существующий счётчик/рейтинг из KV; старые `id:*` и `notified_reg:*`
учитываются для дедупликации. Основное состояние живёт в SQLite Durable Object,
а KV получает совместимый снимок раз в минуту. Чтение рейтинга и общих счётчиков
в приложении/админке идёт через Durable Object. Старый `users_list` больше не
пополняется: список админки уже строится через `user:*` с метаданными.

Установка/регистрация и событие аналитики фиксируются одной транзакцией через
outbox. Доставка в `StatsBuffer` повторяется с постоянным ID события. Сам буфер
пишет не более 1000 событий за пачку: хранит план итоговых записей до отправки
в KV и при сбое повторяет те же значения. Частично записанная пачка не должна
считаться дважды. Повторный сброс возможен не раньше 65 секунд; обычный интервал
— 5 минут. При большом хвосте очередь догоняет показатели постепенно. Источники
`App Store` / `Google Play` сохраняются, старые ошибочные `direct` не исправляются.

`TelegramQueue` (binding `TELEGRAM`) принимает сообщения в durable-хранилище и
отправляет по одному с интервалом не менее 3,1 секунды. Повторяет сетевые ошибки,
5xx и 429 с учётом `retry_after`; покупки и регистрации имеют ключи дедупликации.
Невалидные сообщения (400) сохраняются отдельно как `failed:q:*` и не блокируют
следующие сообщения. При сбое подтверждения Telegram после фактической отправки
возможен повтор: внешняя доставка не может гарантировать exactly-once.
Установки по-прежнему входят в суточную сводку, отдельные сообщения о них выключены.
Ошибка очереди Telegram не превращает уже подтверждённую покупку в ошибку покупки.

Проверка перед публикацией:

```bash
npm run test:security
npm run test:traffic
npx wrangler deploy --dry-run
```

Деплой должен включать все четыре DO bindings и миграцию `v3-traffic` вместе с
кодом. После активации нельзя откатываться на старый обработчик KV и считать его
данные первичными: новые ID установок и регистрации находятся в Durable Object.
Для отката исправлять текущие обработчики с сохранением bindings/состояния.
Store verification и облачная синхронизация прогресса продолжают использовать KV;
переход рейтинга/счётчиков не является миграцией профилей и подписок.


Обновления с `kind: update` и build >=41 учитываются как `returning` без
увеличения дневных установок и общего счётчика. Для build <41 / отсутствующей
версии тот же признак ненадёжен: событие идёт в `unclassified` дня/слота, также
без увеличения новых установок. Все категории дедуплицируются по install_id.
Переустановка/очистка данных с новым ID технически остаётся новой установкой;
это не счётчик уникальных людей. Накопленные исторические totals автоматически
не пересчитываются: старые маркеры не содержат достаточных данных.
# Telegram: источники и ежедневный график (2026-10-04)

Email в уведомлениях всегда указан: имеющийся адрес, включая Apple Relay
с пометкой «защищённый адрес Apple», либо «не передан провайдером».
Настоящий адрес за Apple Relay не раскрывается и не подставляется.

Регистрация выводит флаг и имя без заголовка «Новая регистрация». Поля:
магазин установки, источник/кампания и способ определения, модель/ОС/язык,
ID аккаунта и приблизительный регион по IP. Обычный Dart user-agent убран
из сообщения. Первый известный источник сохраняется при повторной синхронизации.
У старых клиентов источник отображается как «не определён»; задним числом
устанавливать Threads по IP, устройству или всплеску регистраций нельзя.

Ссылка `https://pdd-drive.ru/links/?ref=threads` учитывает посещения и клики.
`tracker.js` переносит UTM в `referrer` Google Play; Android получает его
через официальный Install Referrer API и передаёт при синхронизации профиля.
Это требует выпуска новой мобильной сборки. Магазин и рекламный источник —
разные поля. На iOS индивидуальная атрибуция обычной установки из App Store
не доступна: `ct` задаёт метку кампании, но для агрегированных отчётов Apple
нужна готовая campaign-ссылка из App Store Connect с обоими `ct` и `pt`.
Имеющийся `pt` сохраняется трекером; без него кампании Apple не обещаем.

Покупки начинаются `⭐⭐⭐⭐⭐⭐⭐⭐`, жалобы — `🚩🚩🚩🚩🚩🚩🚩🚩`.
Сводка содержит покупки, жалобы, посещения/клики Threads и регистрации с
переданной меткой Threads. Счётчики покупок/жалоб появились с этого изменения,
старые покупки не восстанавливаются из сообщений Telegram.

`daily_chart.js` рисует PNG внутри Workers без внешнего сервиса: установки
и регистрации за семь периодов 22:00–22:00 МСК. Отсутствующие слоты обозначены
«Н/Д». TelegramQueue хранит картинку до успешной доставки, повторяет 429 и
сетевые ошибки, при отказе картинки отправляет текст. Если подпись превышает
1024 символа, картинка и полный текст добавляются одной транзакцией в очередь.
Если StatsBuffer ещё не закончил сброс, `tg:daily_pending` сохраняет отчёт;
существующий пятиминутный крон повторяет его. Ключ `daily:<date>` предотвращает
повторный отчёт. Проверки: `npm run test:logging`, `npm run test:traffic`,
`npm run test:security`.

### Аналитика и география

`/admin#analytics` показывает события сайта, первые запуски и новые аккаунты
отдельно: конверсия между этими группами не рассчитывается. Дни календарные,
МСК; последний день неполный. Аккаунты считаются по дате создания профиля.

География новых аккаунтов выбранного периода строится по последним сохранённым
`ipCountry`, `ipRegion`, `ipCity`. Это приблизительная география IP, включая
влияние VPN. Доли считаются среди аккаунтов с известным соответствующим уровнем
географии; интерфейс показывает полноту данных. Активность за 7 дней и Premium
показывают текущее состояние этих же аккаунтов. Старые сводки KV v2 дополняются
географией ограниченными пачками до 150 профилей, максимум 6 одновременно;
старые аккаунты продолжают учитываться в общих счётчиках. Новые записи сразу
сохраняют сводку v3. Проверка: `node --test test-analytics.mjs`.

## Публикации в админке

`/admin#publications` объединяет календарь и список статей, Threads и роликов
Instagram/YouTube. Вкладки `blog`, `threads`, `videos` сохраняют редакторы,
подключения, очереди и массовые действия. Старые ссылки `#blog`, `#threads`,
`#social` автоматически переходят в нужную вкладку.

- `publications_data.js` — общий вид существующих данных; новой очереди нет.
- `publications_ui.js` — план, фильтры, боковая карточка, изменение даты.
- `blog_ui.js` — каталог всех статей через защищённый `GET /api/admin/blog`.
- Все даты/время плана — МСК; социальные очереди хранят `scheduledAt` в UTC.
- Прошедшая дата блога не подтверждает публикацию сайта: текст и деплой
  выполняются через локальную админку блога. Даты воркера описывают план.
- Видео без индивидуальной даты могут публиковаться в окне расписания канала.
  Удаление даты видео возвращает его к этому расписанию, не ставит на паузу.
- Обычное изменение даты Threads сохраняет серверный статус поста, чтобы
  устаревшая карточка не могла повторно поставить опубликованный пост в очередь.

Проверки: `npm run test:publications`. Вёрстка и поведение оболочки изменяются
в модулях; экранированные исходные строки `ADMIN_HTML_HEAD`/`ADMIN_CLIENT_JS`
в `worker.js` остаются историческим шаблоном.

## Визуальная система панели

`admin_theme.js` подключается после стилей разделов и задаёт общие поверхности,
типографику, навигацию, поля и состояния действий. Рамки остаются только там,
где обозначают сетку таблицы или календаря; выбор выделяется заполнением,
клавиатурный фокус — контуром. До 760 px навигация становится горизонтальной,
доска задач прокручивается внутри раздела. `ai_ui.js` хранит разметку ИИ с
прежними управляющими ID. Журналы и настройки обновлений свернуты в `details`.
